# archive 历史版本归档

## 1. 本目录定位

硬件设计的历史版本归档区。设计迭代中被替代的版本移入此处保留，确保设计演进可追溯，同时保持各模块目录整洁（模块目录只保留当前有效版本）。

## 2. 归档规则

1. **归档路径**：被替代的版本移入 `archive/<模块>/<版本>/`。

   ```
   archive/
   ├── README.md
   ├── .gitkeep
   ├── core-board/
   │   └── V1.0/
   ├── pa-module/
   │   └── V1.0/
   ├── lpf-module/
   │   └── V1.0/
   ├── atu-module/
   │   └── V1.0/
   ├── mcu-ui-module/
   │   └── V1.0/
   └── power-module/
       └── V1.0/
   ```

2. **归档内容**：该版本的完整设计资料（原理图、PCB、Gerber、BOM、结构件、测试报告），保持目录结构不变，便于整体回溯。
3. **必须保留的信息**（在归档目录内以 `ARCHIVE-NOTE.md` 记录）：
   - **原始发布日期**（该版本首次发布/投产日期）。
   - **替代原因**（为何被替代：指标不达标、器件停产、成本优化、装配问题等）。
   - **替代版本**（被哪个版本取代）。
   - **已知问题**（该版本的遗留缺陷与规避方法）。
4. **版本号格式**：`V<主>.<次>`，例如 `V1.0`、`V1.1`、`V2.0`。
5. **不可删除**：归档内容不得删除或覆盖；如需废弃整个版本，追加说明而非移除文件。

## 3. 与模块目录的关系

| 位置 | 保留内容 |
|------|---------|
| `hardware/<模块>/`（如 `atu-module/`） | **仅当前有效版本** |
| `hardware/archive/<模块>/<版本>/` | 被替代的历史版本 |

## 4. 目录内容

| 路径 | 内容 |
|------|------|
| `README.md` | 本文件 |
| `.gitkeep` | 占位文件（保持空目录入版本库） |
| `<模块>/<版本>/` | 归档的历史版本资料（创建后出现） |

## 5. 验证要点

- 每次版本替代后确认：模块目录已切换到新版本，旧版本已完整移入 `archive/`。
- 每个归档目录均含 `ARCHIVE-NOTE.md`，且发布日期与替代原因已填写。
- 归档资料可通过 Gerber 重新制板复现该版本（文件完整性检查）。

## 1. 独立验算：8 + 8 组合表，以及拓扑的唯一性

> 本节**不采信** `atu-module/README.md` §2 的组合值表，而是从三只元件的标称值出发重新穷举，
> 再与文档值逐项比对。可一键复现：`python scripts/verify-atu-lc-combos.py`。

### 1.1 方法

3 只元件 ⇒ 每只「在电路里 / 不在电路里」两态 ⇒ **2³ = 8 种**。

- **串联支路**（三只元件全部串联）：在电路里的元件串联求和 ⇒ 8 个子集和。
- **并联支路**（三只元件全部并联）：在电路里的元件并联求和（倒数相加）⇒ 8 个子集和。

「不在电路里」在串联支路里只能靠**并联短接**实现（断开＝整条链断路），在并联支路里只能靠**串联断开**实现。这就是后面 §1.4 的判据。

### 1.2 电感侧：8 个子集和（单位 µH）

| mask（LSB=L1） | 在电路里的元件 | 求和算式 | 等效电感 |
|---|---|---|---|
| `000` | （无，三只全旁路） | — | **0** |
| `001` | L1 | 12 | **12** |
| `010` | L2 | 33 | **33** |
| `011` | L1 + L2 | 12 + 33 | **45** |
| `100` | L3 | 47 | **47** |
| `101` | L1 + L3 | 12 + 47 | **59** |
| `110` | L2 + L3 | 33 + 47 | **80** |
| `111` | L1 + L2 + L3 | 12 + 33 + 47 | **92** |

排序后：**{0, 12, 33, 45, 47, 59, 80, 92}** —— 与 `atu-module/README.md` §2 的
`0/12/33/45/47/59/80/92 µH` **逐项完全一致** ✅

**可逆性**：8 个和两两互异（最小间隔 2 µH，出现在 45 与 47 之间）⇒
由测得的等效电感可以**唯一反查**继电器组合，不存在二义性 ✅

### 1.3 电容侧：8 个子集和（单位 pF）

| mask（LSB=C3） | 在电路里的元件 | 求和算式 | 等效电容 |
|---|---|---|---|
| `000` | （无，三只全断开） | — | **0** |
| `001` | C3 | 22 | **22** |
| `010` | C4 | 120 | **120** |
| `011` | C3 + C4 | 22 + 120 | **142** |
| `100` | C5 | 330 | **330** |
| `101` | C3 + C5 | 22 + 330 | **352** |
| `110` | C4 + C5 | 120 + 330 | **450** |
| `111` | C3 + C4 + C5 | 22 + 120 + 330 | **472** |

排序后：**{0, 22, 120, 142, 330, 352, 450, 472}** —— 与文档值
`0/22/120/142/330/352/450/472 pF` **逐项完全一致** ✅（8 个值两两互异，可逆 ✅）

### 1.4 竞争拓扑必须被排除（否则「唯一性」是空话）

| 竞争方案 | 能得到的 8 个值 | 与文档值比对 |
|---|---|---|
| 电感**并联**（每只串一只开关） | `∞ / 12 / 33 / 47 / 8.8 / 9.525 / 19.388 / 6.847` µH | ❌ 45 / 59 / 80 / 92 **全都得不到** |
| 电感**串联但每只串一只开关** | 断开任意一只 ⇒ **整条链断路**（开路），无法得到「其余三只仍然导通」的中间档 | ❌ 结构上不成立 |
| 电容**串联**（每只串一只开关） | `∞ / 22 / 120 / 330 / 18.592 / 20.625 / 88.0 / 14.4` pF | ❌ 142 / 352 / 450 / 472 **全都得不到** |
| **电感串联 + 每只并联旁路**（本文结论） | 子集和 = 文档 8 值 | ✅ |
| **电容并联 + 每只串联接入**（本文结论） | 子集和 = 文档 8 值 | ✅ |

> 脚本 C1/C2/C3 三项检查即为此表，全部通过。

### 1.5 验算结论（含对"我的反推"的更正）

1. **拓扑反推正确** ✅：电感＝「三只串联 + 每只并联旁路」，电容＝「三只并联 + 每只串联接入」，
   8 个值**恰好就是** 2³ 子集和，且两组 8 值都可逆。原反推的这一部分**成立，已独立复现**。
2. 🔴 **但"每只电感用 COM/NO 跨接"这一句在极性上是错的**（这是本轮验算的新发现）：
   - `COM–NO` 跨接在电感两端 ⇒ **吸合＝短路＝旁路**，**释放＝电感接入** ⇒
     上电「全部释放」的等效电感是 **92 µH**（三只全在电路里），**不是 0 µH**；
   - 而**组合表本身只约束"哪些元件在电路里"，完全不约束"吸合是接入还是旁路"** ——
     极性无法从数值表推出，只能由系统契约（固件）锁定；
   - 固件契约明确要求 **`mask = 0` ⇒ 0 µH / 0 pF 直通**（§4.3），因此硬件**必须把旁路触点改用 `COM–NC`**
     （方案 A）。若按原文的 `COM–NO` 打样，则**上电默认态变成 92 µH**，与固件 `ATU_MATCH_SAFE_COMBO = 0`
     的语义冲突，属于「打样出来不工作」级别的错误。
3. 电容侧的 `COM–NO` 串联与原反推**一致且正确** ✅（吸合＝接入，释放＝断开）。

## 2. 拓扑：完整的射频通路与逐脚接法

### 2.1 完整射频通路（方案 A）

```text
                      ┌──────────────── 串联 L 链（接源侧）──────────────────────┐
   RF_IN              │  N0               N1               N2              N3    │   RF_OUT
 (J_ATU_IN) ──────────┤───┬───[L1 12µH]───┬───[L2 33µH]────┬───[L3 47µH]────┬────┼──── (J_ANT)
 来自 lpf-module      │   │               │                │                │    │    天线座
  （SMA 50Ω）          │   └── K1 ────────┴── K2 ──────────┴── K3 ──────────┘    │
                      │      跨接 L1 两端     跨接 L2 两端      跨接 L3 两端      │
                      │      触点用 COM–NC：释放 = 短路 = 该电感被旁路           │
                      └──────────────────────────────────────────────────────────┘

    N3 = 天线侧节点 = 天线 + 并联电容支路 的公共节点
    ├── K4.COM ──[NO]── C3 22pF ──┐
    ├── K5.COM ──[NO]── C4 120pF ─┼───────────────────────── GND
    └── K6.COM ──[NO]── C5 330pF ─┘
```

**每只电感的旁路细节（以 K1 为例，K2/K3 同构）**

```text
   N0 ──┬──────────[ L1 12µH ]──────────┬── N1
        │                               │
        └──── K1.COM         K1.NC ─────┘
              （K1 释放：COM–NC 闭合 → L1 被短路 → L1 不在电路里）
              （K1 吸合：COM–NC 断开 → L1 串入 → 12µH 接入）
```

**每只电容的接入细节（以 K4 为例，K5/K6 同构）**

```text
   N3 ── K4.COM      K4.NO ──── C3 22pF ──── GND
         （K4 释放：触点断开 → 该支路无电流 → 0 pF 接入）
         （K4 吸合：触点闭合 → 22 pF 并在 N3 与 GND 之间）
```

**网表节点名（与 `hardware/schematic/netlist.csv` 严格一致，勿另起名）**

| 节点 | 网表网络名 | 该节点上的引脚 |
|---|---|---|
| N0（L 链入口，来自 lpf-module / 耦合器主线） | `ATU_L_IN` | `J_ATU_IN.中心`、`L1.1`、`K1.COM` |
| N1（L1 与 L2 之间） | `ATU_L1_LO` | `L1.2`、`L2.1`、`K1.NC`、`K2.COM` |
| N2（L2 与 L3 之间） | `ATU_L2_LO` | `L2.2`、`L3.1`、`K2.NC`、`K3.COM` |
| N3（L 链输出 = 天线节点 = 并联 C 节点） | `ATU_L3_LO` | `L3.2`、`J_ANT.中心`、`K3.NC`、`K4.COM`、`K5.COM`、`K6.COM`、`R_esd.1`（天线泄放） |
| C3/C4/C5 的冷端 | `GND` | `C3.2`、`C4.2`、`C5.2` |

### 2.2 L1 / L2 / L3 的串联顺序：为什么是 L1 → L2 → L3

🔴 **先说清楚一件事：串联顺序在电气上没有任何影响。**
理想串联网络的输入阻抗是 `Z = ΣZᵢ`（加法可交换），三只电感的串入/旁路组合也**不含位置信息**
（8 个和只由"哪几只被旁路"决定）。**组合表无法、也不应该被用来推断顺序**——
任何"按组合表唯一性定顺序"的说法都是不成立的。所以顺序只能按工程理由选：

| 理由 | 说明 |
|---|---|
| ① 与软件位序/丝印同向 | 固件 `relay_mask` bit0 = K1 = L1、bit1 = K2 = L2、bit2 = K3 = L3（§4.3）。让 **物理次序与软件序号同向**，逐位调试（"只动 bit0 看 SWR 怎么变"）时不必在脑子里做映射，排错最快、错装最容易被发现 |
| ② 磁环尺寸单调 | T37-6（外径 9.5 mm）→ T106-6（26.9 mm）×2。小磁环放靠 **RF_IN** 侧、大磁环放靠 **天线** 侧，L 链一列排布时体积递增不打架，两条支路（L 链 / C 支路）在 PCB 上分区干净 |
| ③ 与网表/丝印一次性定死 | 顺序一旦写进丝印与网表，**今后不要改**：改顺序要同步改丝印、网表、装配图与调试脚本，收益为零 |
| ❌ "小电感在前利于高频旁路" | **不是有效理由**：串联支路里所有元件流过**同一个电流**，不存在"前/后"对高频分流的差别 |
| ❌ "按组合表唯一性" | **不成立**：见本节开头，组合表不含位置信息 |

> 若因布板必须反过来（L3 靠 RF_IN），**功能不受影响**，但必须同步改丝印与网表，
> 并且**不能**改动"K1↔L1、K2↔L2、K3↔L3"这个对应关系（那是固件契约）。

### 2.3 并联电容接在哪一侧：`SHUNT_C_AT_LOAD`（天线侧）

L 型网络有两种镜像接法（固件 `atu_match.h` 里定义为 `ATU_MATCH_PLACEMENT_*`）：

| 接法 | 适用条件（固件判据） | 本工程是否需要 |
|---|---|---|
| `SHUNT_C_AT_LOAD` | 并联 C 接**负载（天线）侧**、串联 L 接向源 | ✅ **需要**（本工程天线 \|Z\| ≈ 1057 Ω ≫ 50 Ω） |
| `SERIES_L_AT_LOAD` | 串联 L 接负载侧、并联 C 接源侧 | ❌ 不采用 |

**反证（用 `atu-module/README.md` §6 自己的判据逐字命中）**——

| README §6 判据 | `SHUNT_C_AT_LOAD` 最优 | `SERIES_L_AT_LOAD` 最优 | 结论 |
|---|---|---|---|
| 挂树 `120−j1050Ω`：**33 µH 档** SWR < 2.5 | **2.193**（33 µH + 22 pF）✅ | 2.401（47 µH + 0 pF） | 判据点名的就是 **33 µH + 22 pF**，只有 `SHUNT_C_AT_LOAD` 命中 |
| 实验室 `88−j1030Ω`：**45 µH 档** SWR < 2.0 | **1.980**（45 µH + 0 pF）✅ | 1.838（47 µH + 120 pF） | 判据点名的 **45 µH** 只有 `SHUNT_C_AT_LOAD` 命中 |
| 实验室 `50−j1110Ω`：**47 µH 档** SWR < 1.8 | 3.209（47 µH）❌ | 3.209（47 µH）❌ | ⚠️ 两种接法都达不到，见 §6 附带发现 |

**解析校核**（超定）：对 `120−j1050Ω @3.55 MHz` 精确求解「并联 C（天线侧）+ 串联 L」，
得 **L = 30.50 µH、C = 23.40 pF**，与 README §2「挂树 30–34 µH（选 33 µH）、并联电容约 25 pF」
完全吻合；而这两种元件值**只有在 C 挂在负载侧时才同时被需要**（若 C 挂源侧，最优解是 47 µH + 0 pF，
与工程实测的"需要并联电容"矛盾）。✅

> 🔴 **投板含义（软硬件契约）**：硬件只有**一种**固定接法，**必须**是 `SHUNT_C_AT_LOAD`。
> 相应地，固件 `atu_match_predict_default()` 当前默认 `ATU_MATCH_PLACEMENT_AUTO`
> 必须在上层**裁成 `SHUNT_C_AT_LOAD`**，否则预测模型与实际网络不符，
> 搜索排序会给出错误的最优组合（`atu_match.h` §匹配预测 已把这条列为"唯一硬件未知量"）。
> 该"固化"动作属固件侧（私有仓），本文只提出要求，**不修改固件**。

## 3. 继电器 ↔ 组合表映射（核心交付）

### 3.1 索引方式（与固件逐字一致）

```text
relay_mask  bit i  ⇔  K(i+1)  ⇔  TCA9535 P0.i  ⇔  ULN2003A IN(i+1)/OUT(i+1)
  bit0 = K1 = L1 12µH      bit3 = K4 = C3  22pF
  bit1 = K2 = L2 33µH      bit4 = K5 = C4 120pF
  bit2 = K3 = L3 47µH      bit5 = K6 = C5 330pF

index = ind_bits | (cap_bits << 3)        ind_bits = mask & 0x07 , cap_bits = (mask >> 3) & 0x07
⇒  数值上  index == relay_mask
⇒  总的 64 种组合 = 8 种电感组合 × 8 种电容组合（笛卡尔积）
```

**含义**：`index` 的低 3 位是电感档、高 3 位是电容档；`index` 与 `relay_mask` 是同一个数，
搜索 / NVS 记忆 / 日志 / 丝印**只用一个编号**，杜绝"两套编号对不上号"。
`mask` 的高 2 位（bit6/bit7 = P0.6/P0.7）**恒为 0**，固件 `decode()` 遇到即报错。

## 4. 驱动侧对齐（TCA9535 → ULN2003A → 继电器线圈）

### 4.1 链路与极性（含"ULN2003A 是反相驱动"的正确理解）

```text
ESP32 GPIO4/5 (I²C) → TCA9535(P0.0–P0.5) → ULN2003A(IN1–IN6 → OUT1–OUT6) → K1–K6 线圈低边
                                                                           K1–K6 线圈另一端 → +12 V
U2.COM  必须接 +12 V（内部续流二极管靠它生效）—— docs/05 §2.4 / 预打样清单 D-01
U2.IN1–IN6 各加 10 kΩ 下拉到 GND（上电安全，本文 §4.2 新增，预打样清单 D-20）
```

| 环节 | 逻辑 | 电平 |
|---|---|---|
| TCA9535 输出锁存器位 | `1` | 引脚**输出高**（3.3 V） |
| ULN2003A 输入 | 高（> V_I(on) ≈ 2.4 V） | 达林顿**饱和导通** |
| ULN2003A 输出 OUTn | **拉低到 GND**（V_CE(sat) ≈ 0.9 V） | ← **"反相"发生在这一级** |
| 继电器线圈 | 两端 11.1 V（= 12 − 0.9） | **吸合**（HK4100F 吸合阈值 75 % × 12 V = 9 V，余量足） |

> 🔴 **回答"TCA9535 位 = 1 时继电器是吸合还是释放"**：
> **吸合。** ULN2003A 的"反相"是**相对它自己的输入/输出**而言的（输入高 → 输出低）；
> 而 TCA9535 位 = 1 ⇒ ULN 输入 = 1 ⇒ 输出低 ⇒ 线圈得电 ⇒ **吸合**。
> 所以从**软件 `relay_mask` 位到"吸合"是直接（非反相）**的：
> **位 = 1 ⇔ 吸合 ⇔ 该元件接入**；位 = 0 ⇔ 释放 ⇔ 该元件不接入。

### 4.2 🔴 上电默认态核验（结论：等效 0 µH / 0 pF，但**必须**补 6 只下拉电阻）

| 阶段 | TCA9535 的 I/O 状态 | ULN2003A 输入 | 线圈 | 继电器 |
|---|---|---|---|---|
| 芯片刚上电（固件未跑） | **输入**（方向寄存器上电默认全 1 = 输入），引脚不被驱动；**但输入带约 100 µA 弱上拉电流源** | ⚠️ 若无外部下拉，被弱上拉拉高 → **半开/误导通风险** | 可能得电 | ⚠️ 可能误吸合 |
| 加了 **10 kΩ 下拉**后 | 同上 | 100 µA × 10 kΩ = **1.0 V ≪ V_I(on) ≈ 2.4 V** | **不通电** | ✅ **释放** |
| 固件 `ioexp_init()` / `relay_init()` 之后 | 极性全 0 → **输出锁存器先清 0** → 最后才把 K1–K6 设为输出（`bsp_io_expander.c` 的 `ioexp_reset_to_safe()`：极性 → 锁存器 → 方向，**顺序是对的**），随后读回校验"确实全 0" | 低 | 不通电 | ✅ **释放（上电安全态）** |

**核验结论**

1. ✅ 上电等效 L/C = **0 µH / 0 pF**（直通）——与固件 `ATU_MATCH_SAFE_COMBO = 0`、`index = 0 = 直通` 一致。
2. ⚠️ **但"TCA9535 上电 I/O 是输入高阻"这个说法不完整**：TCA9535 的输入端口带
   **约 100 µA 的弱上拉电流源**（这也是固件头文件里明确写下的前提），
   因此"ULN2003A 输入无上拉 ⇒ 输出高阻 ⇒ 线圈不通电"这一步**只有在 ULN 输入加了外部下拉时才成立**。
   → ⛔ **硬件必须为 IN1–IN6 各加一只 10 kΩ 下拉到 GND**（6 只）。
   这条此前**不在** BOM、也不在预打样清单里，**本轮新增**（见
   [`hardware/pre-fab-checklist.md`](../pre-fab-checklist.md) D-20、
   [`hardware/bom/bom-atu-module.csv`](../bom/bom-atu-module.csv) 的 `R_RLY1-R_RLY6`）。
3. ✅ 固件侧的初始化顺序**已经是安全的**（先清锁存器再切输出方向），
   配合硬件下拉构成"两道保险"；固件在扩展器缺失时的日志也明确写了
   "relays held released by hardware pulldown"，即**固件把这条硬件下拉当作既定前提**。

### 4.3 软件 `relay_mask` 契约（软硬件接口契约，写错就白打样）

> 来源：**私有固件仓**（只读引用，本文不改）
> `components/drv_relay/include/drv_relay.h`、`components/atu_match/include/atu_match.h`、
> `components/drv_relay/src/drv_relay.c`、`components/atu_match/src/atu_match.c`

| 契约项 | 内容 |
|---|---|
| 位序 | `bit0 = K1`、`bit1 = K2`、`bit2 = K3`、`bit3 = K4`、`bit4 = K5`、`bit5 = K6`；`bit6/bit7` 保留，**必须为 0** |
| 极性 | `1 = 吸合`（= 该元件**接入**）；`0 = 释放`（= 该元件**不接入**）。**非反相** |
| 索引 | `index = ind_bits \| (cap_bits << 3)`，且 **`index` 与 `relay_mask` 数值相同**（`encode()` 即恒等映射） |
| 元件的"接入" | 电感：**串联求和**（接入 = 串入）；电容：**并联求和**（接入 = 并入） |
| 落地位 | `relay_set_mask(mask)` / `relay_set_mask_forced(mask)`（后者**绕过发射互锁**）→ `ioexp_write_port_masked(PORT0, mask, 0x3F)` → TCA9535 P0.0–P0.5 |
| 切换时序 | **先断后合**（先清除要释放的位并等 5 ms，再置位要吸合的位并等 8 ms），且 mask 不变时**不动作**（省电气寿命，HK4100F 仅 10 万次） |
| 发射互锁 | 发射中调用非 `forced` 版本会被拒（`ARDF_ERR_RELAY_TX_ACTIVE`）；发射中途检测到互锁会停在"全释放"这个确定态 |
| 上电安全态 | `relay_init()` 把掩码写 0 并**读回校验**；`ATU_MATCH_SAFE_COMBO = 0` |

**由此得到的接线准则（本文 §2.4 即按此确定）**

```text
mask bit = 1  ⇒  K 吸合  ⇒  该元件"接入"  ⇒
   电感：该电感的旁路触点必须"断开" ⇒ 旁路触点用 COM–NC（方案 A）
   电容：该电容的支路触点必须"闭合" ⇒ 支路触点用 COM–NO
mask = 0（全释放）⇒ 电感全部被旁路（0 µH）、电容全部断开（0 pF）⇒ 直通
```

> 固件头文件自己给出了这条推理的"逃生门"：*"若日后原理图证明某位是『吸合=旁路』，
> 只需 atu_match 反相它的表，本组件不动。"* —— 本文的选择是**让硬件去符合既有固件契约**（方案 A），
> 而不是改固件，因为 `index=0 = 直通` 已被 README、契约与多处测试引用（改动面更大、更易漏）。

### 4.4 驱动侧电气校核（复核既有结论，无异议）

| 项 | 数值 | 判据 | 结论 |
|---|---|---|---|
| 单路线圈电流 | 12 V / 720 Ω = **16.7 mA** | ULN2003A 500 mA/路 | 余量约 30 倍 ✅ |
| 6 只同时吸合 | ≈ **100 mA** | < 110 mA（stage-1 判据） | ✅ |

## 6. 附带发现（不阻塞投板，但需复核文档判据）

**`atu-module/README.md` §6 / `validation/stage-2` §5 的"实验室 `50−j1110Ω`：47 µH 档 SWR < 1.8"在当前元件集下不可达。**

穷举全部 64 组合（含两种 L 型镜像接法）在 3.50–3.60 MHz 的结果：

| 接法 | 该负载下最优 SWR | 最优组合 |
|---|---|---|
| `SHUNT_C_AT_LOAD` | **2.719** | 33 µH + 22 pF |
| `SERIES_L_AT_LOAD` | **3.209** | 47 µH + 0 pF |

- 判据点名的 `47 µH 档`：`Z = 50 − j1110 + j·2πf·47 µH = 50 − j62` ⇒ SWR ≈ **3.2**（两种接法在这一档完全相同）。
- 要 SWR ≤ 1.8 需 `|X| ≤ 29.8 Ω` ⇒ `L ∈ [48.4, 51.1] µH`；而现有 8 个电感档里最接近的是
  **47 µH（→3.21）** 与 **59 µH（→18.92）**，**都不满足**。
- 对比：同一判据表里 `88−j1030Ω` 在 `SERIES_L_AT_LOAD` 下能到 1.838（47 µH + 120 pF），
  但那是**另一个负载**，不能用来支撑 `50−j1110Ω` 这一行。
- 建议（二选一）：① 把该判据放宽为「`50−j1110Ω` 的 47 µH 档 SWR < 3.3」；
  ② 若确实要 < 1.8，需把 L3 由 47 µH 改为约 **49–51 µH**（并重新验算 47 µH 档所服务的其它负载）或增设一档。
  **在实测（stage-2 步骤 6）之前不要把它当作出厂验收线**。属**文档判据**问题，**不影响 §1–§4 的接法结论**。

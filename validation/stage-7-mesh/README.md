# stage-7-mesh —— Mesh 组网与遮挡回传

- 时间窗：第 19–20 天
- 状态：未开始

> **软件侧验证**：本阶段无独立硬件判据，验证对象是固件 Mesh 组件。
> 对应固件组件：**`net_espnow`**（ESP-NOW 收发封装）、**`mesh_router`**（路由/转发/去重）。

## 1. 验证目标

在野外场地条件下验证多节点组网与转发能力：当主控与其中一台从机被地形遮挡时，
回传数据能否借由第三台从机中继成功送达。

## 2. 被测对象

- `net_espnow` 组件：ESP-NOW 收发、信道与速率配置、MAC 白名单
- `mesh_router` 组件：邻居表维护、洪泛/选路、跳数与去重、`TELEMETRY` 回传路径
- 3 台从机 + 1 台主控的实机组合

## 3. 仪器与工装

- 4 台整机（3 从机 + 1 主控），均已烧写固件并完成 ATU 调谐
- 中控 PC（或主控串口终端）用于统计回传成功率
- 遮挡工装：地形遮挡（坡地、建筑拐角）或金属屏蔽板
- 秒表、笔记本（记录场次与位置）
- 现场尽量不要有其他 2.4GHz 强干扰源，需记录环境

## 4. 步骤

1. 在开阔场地布设 3 台从机与 1 台主控，确认全部入网、`HELLO` 正常。
2. 记录基线：无遮挡条件下连续 10 分钟 `TELEMETRY` 回传成功率。
3. 按计划在**主控与其中 1 台从机之间**加入遮挡（如坡地/建筑拐角），
   使该从机与主控直连链路基本中断。
4. 保持第三台从机位置可同时"看到"主控与该被遮挡从机，形成中继路径。
5. 连续运行 10 分钟，统计被遮挡从机的回传成功率（以主控收到为准）。
6. 记录跳数分布、重传次数、丢包位置（直连失败 vs 中继失败）。
7. 移除遮挡，确认链路自动恢复且成功率回到基线水平。
8. 记录现场 2.4GHz 环境干扰情况与信道选择。

## 5. 判据

| 指标 | 判据 | 实测 | 结论 |
| --- | --- | --- | --- |
| 组网 | 3 从机 + 1 主控全部入网，`HELLO` 正常 | | |
| 遮挡条件下回传成功率 | **>80%** | | |
| 中继生效 | 被遮挡节点数据经由第三台从机送达 | | |
| 链路恢复 | 遮挡移除后成功率回到基线 | | |
| 去重与跳数 | 无重复帧上送，跳数受控 | | |
| 现场干扰记录 | 记录信道与干扰源 | | |

## 6. 数据与报告

- 回传统计日志（`.csv`：时间戳、发送数、收到数、跳数）放 `raw/`。
- 实测报告：`report-YYYYMMDD.md`，须写明场地位置、遮挡物性质与两侧天线朝向。

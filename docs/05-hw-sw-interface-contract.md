## 1. GPIO 资源约束分析

### 1.1 ESP32-C3 可用 GPIO

ESP32-C3 标称 22 个 GPIO，但实际可用受限：

| 引脚范围 | 状态 | 说明 |
|---------|------|------|
| GPIO0 – GPIO10 | **10 个可用** | GPIO0–4 为 ADC1_CH0–CH4；GPIO2/GPIO8 为 strapping 引脚 |
| GPIO11 | **不可用** | VDD_SPI（eFuse 未解锁），**已决定不解锁** |
| GPIO12 – GPIO17 | **除 12/13 外不可用** | 其余内部连接 SPI Flash；**GPIO12/13 在 DIO 模式下可用**（见 §2.1、§2.6.1） |
| GPIO18 – GPIO19 | **不可用** | 原生 USB D−/D+（本板主控制台） |
| GPIO20 – GPIO21 | 🔴 **本版回收（2026-10-11）** | 原为 UART0；因主控制台已在**原生 USB-Serial/JTAG**，本版把两脚改作 **GPIO20=`EC11_A`、GPIO21=`LCD_BL`**（"无串口版"，见 §2.1/§2.2） |
| **合计可用** | **12 个** → 🔴 **本版实得 14 个** | 0–8、10、12、13（12 个）+ **20、21 回收（+2）**；明细见 §2.1/§2.2 |

> 上一版此处写「合计 15 个」并把 GPIO18–21 计为可用，与 §2.1「不可用」自相矛盾；
> 现已按 §2.1 的权威口径统一为 **12 个**。

**ADC 约束**

| 项 | 说明 |
|----|------|
| ADC1 通道 | **GPIO0–GPIO4（5 通道）**，出厂标定，**可在 WiFi 工作期间使用** |
| ADC2 通道 | **ESP32-C3 的 ADC2 只有 1 个通道，即 GPIO5**；未出厂标定，且与 WiFi 冲突，**部分芯片版本根本不可用** |
| 结论 | → 所有模拟量必须落在 **GPIO0–GPIO4** 上，最多 5 路 |

### 1.2 需求侧引脚统计

| 类别 | 需求 | 数量 |
|------|------|------|
| 模拟输入 | 前向检波、反向检波、电池电压、（备用：电源电流） | 3–4 |
| I2C | Si5351 + TCA9535 + LCD | 2 |
| 数字输出（慢速） | 继电器 K1–K6、~~蜂鸣器~~、~~PA_EN~~、LCD RST、~~LCD 背光~~ | 11 → **本版缩为 6 继电器**（蜂鸣器 ❌ 本版不做；背光改走 GPIO21，不占扩展器；🔴 **`PA_EN` 不存在** —— 键控走 Si5351 输出使能，见 §2.5/§4.2） |
| 数字输入（慢速） | EC11 A/B/SW、按键 ×2 | 5 |
| 快速数字 | CW 键控、功放功率 PWM | 2 |
| 调试 | UART0 或原生 USB | 2 |
| **合计** | — | **26–27** |

**结论**：需求（26–27）远超可用 GPIO（15），**必须使用 I/O 扩展器**，且显示接口必须走少引脚方案。

### 1.3 分配决策

见 [ADR-0004](adr/ADR-0004-lcd12864-on-shared-i2c.md)：

- **LCD 走 SPI2 独占**（ST7567 仅支持 SPI）：`CS` 接 GND（总线唯一从机）、`RST` 与板复位共用 → 省 2 个 GPIO；I²C 总线只留 Si5351 与 TCA9535。
- **全部慢速 IO 挂 TCA9535**（16 位 I2C 扩展器）→ 释放 11 个 GPIO。
- **稀缺 GPIO 留给**：ADC（GPIO0–3）、I²C（GPIO4/5）、SPI 显示（GPIO6/7/10）、
  功放功率 PWM（GPIO12）、EC11 A/B（GPIO2/8）、编码器按键（GPIO13）。
  **CW 键控不占任何 GPIO**（走 Si5351 使能命令，见 §2.5）。

> 上一版此处的「CW 键控（GPIO7）、功放功率 PWM（GPIO8）」是 ADR-0008 之前的旧方案，
> 与 §2.2 的最终分配不符，已按 §2.2 更正。

**不占用 GPIO 的连接**：

| **CW 键控** | **Si5351 使能命令**（I²C 写 `CLKx_DIS`） | 完全不占 GPIO，见 §2.5 |
| **LCD 背光** | 🔴 **不再借 I/O 扩展器，改走 GPIO21（0/1 输出）** | 原方案把背光挂在 TCA9535 P1.1；扩展器移除后一度"待定" → **2026-10-11 定案：直连 GPIO21**（本版权衡：GPIO20/21 已随"无串口版"回收，背光不再需要第二颗 CA-DV8008 `0x29`） |

**LCD 可见列窗口（132 列驱动 / 128 列面板）** —— 液晶模组的几何也是软硬件接口的一部分：

- ST7567 有 **132 个列驱动器**（SEG0..SEG131），12864 面板的可见区只有 **128 列**，
  即可见的 128 列只是 132 个 SEG 里的一段连续窗口 `SEG[W0 .. W0+127]`（`W0 ∈ {0, 2, 4}`）。
- 固件必须在**列地址设置处**补上这个起点：帧缓冲第 x 列 → 芯片列 `W0 + x`
  （私有仓 `components/drv_lcd12864/private_include/st7567_cmds.h: LCD_COL_OFFSET`，
  生效点 `drv_lcd12864.c: panel_set_page_col()`；**不在 UI 的绘制坐标里补偿**）。
- ⚠️ **`W0` 与 SEG 方向位（ST7567 的 ADC 指令 `0xA0`/`0xA1`）是耦合的**：交换 SEG 方向时窗口
  从另一端开始填，`W0` 随之变成 `4 − W0`（上游 u8g2 的 `default_x_offset` / `flipmode_x_offset`
  正好是 0 与 4 这一对）。**定论顺序：先定方向位，再定 `W0`。**
- ✅ **本板已定：`W0 = 0`（面板 180° 安装，方向位 `0xA0` + `0xC8`）**。私有仓把它做成
  **一个宏** `LCD_MOUNT_180 = 1`，**同时**产生方向位与 `W0`（`#else` 支给出 `0xA1`+`0xC0` / `4`），
  结构上不可能只改一个。依据（2026-09-26）：用户拍板本机面板旋转 180° 安装；
  u8g2 `u8x8_d_st7567.c` 的 default/flipmode 两个 `x_offset` 恰是 4 与 0；
  参考项目 BBcall_APRS 在 180° 安装下的实板实测值就是 0。
  ⚠️ **若改安装方式或换模组，方向位与 `W0` 必须同步重定**（换模组会换 SEG 走线）：
  在帧缓冲画 x=0 与 x=127 两条 1 像素竖线，看两条是否都可见、两侧各留几列空白 → 直接读出 `W0`。
  预览工具：私有仓 `tools/lcd-sim`（`--col-offset 0/2/4`、`--mount180`）。见 §7 待冻结事项 #10。

### 2.3 CA-DV8008 I²C 八通道低边驱动（ATU 继电器）

**器件**：**CA-DV8008N**（川土微，SOIC-16N/TSSOP-16，立创 **C54557228**），I²C **7 位地址 `0x28`**
（A2/A1/A0 全部接 GND；器件地址 = `0101 000`，8 位写字节 `0x50` / 读字节 `0x51`；地址范围 `0x28`–`0x2F`，同总线最多 8 片）。

| 端口 | 功能名 | 方向 | 说明 |
|------|--------|------|------|
| OC1 – OC6（脚 16…11） | `RELAY_K1_COIL` … `K6` | O | **ATU 6 个继电器线圈低边**（HK4100F-**DC5V**-SHG，40 mA/只） |
| OC7 / OC8（脚 10 / 9） | — | O | 🔴 **保持空闲、不预接、固件点不到**（2026-10-11 用户明确要求"不要动，空着"）：**不得预接**任何负载；固件侧对应位**不得配置、不得写入**（避免越权占用将来的第二个调用者）——见 §7 #2a / #11 |
| COM（脚 8） | `+5V` | P | 🔴 **内部续流钳位二极管共阴，必须接继电器线圈电源 `+5V`** |
| VCC（脚 1） | `+3V3_DIG` | P | 🔴 逻辑电源 **必须 3.3 V**：输入门限 `V_IH = 0.7×VCC`，若接 5 V 则 `V_IH = 3.5 V` > I²C 总线高电平 3.3 V ⇒ **读不到高电平** |
| A0/A1/A2（脚 5/6/7） | `GND` | I | 地址配置（内部弱下拉，须显式接 GND 或 VCC） |

**寄存器模型（与 TCA9535 的差异）**：**只有 1 个 8 位输出寄存器** —— 写 `1` = 该通道导通（下拉到 GND）、写 `0` = 关断（**输出高阻**）；只支持**单字节写**，并支持**单字节读回**（可做写后校验）。
🔴 **无输入端、无极性反转寄存器、无中断脚** ⇒ 原 `IOEXP_*` 位契约（16 位 + INT + SPARE 位）**作废**，驱动层改为「设备 `0x28` + 通道 `1..8`」模型。

**上电安全态**：寄存器复位为 0 ⇒ 8 路全部**高阻** ⇒ 线圈无电流 ⇒ **K1–K6 全释放 = 0 µH/0 pF 直通**，与固件 `ATU_MATCH_SAFE_COMBO = 0` 天然一致（不再需要 ULN2003A 时代的 `R_RLY1–6` 输入下拉）。

**背光（✅ 2026-10-11 定案：GPIO21）**：原 `IOEXP_LCD_BL`（TCA9535 P1.1）**已随扩展器移除**。

| 项 | 定案 |
|----|------|
| 驱动源 | **ESP32-C3 `GPIO21`（`BOARD_LCD_BL`）**，**0/1 输出，不用 PWM**（背光只需开/关两态） |
| 驱动级 | **低边 MOS**（2N7002 级）：GPIO21 → 栅极，漏极接背光 LED 阴极串（`LCD_BL_K`），源极 GND |
| 🔴 失效安全 | **栅极 100 kΩ 下拉到 GND**（`R_BL2`）⇒ MOS 在 GPIO21 高阻（复位默认态、固件未初始化）时**可靠截止** ⇒ **上电默认低 = 背光关** |
| ✅ 取消的候选 | ~~主板另加一颗 CA-DV8008（`0x29`，A0 接 VCC）承载背光~~ → **不再需要**（GPIO20/21 已在"无串口版"下回收，见 §2.1/§2.2） |
| 与扩展器余量的关系 | OC7/OC8 **保持空闲、不预接**（见上表），背光**不占用** CA-DV8008 任何通道 |

> 📌 **蜂鸣器：❌ 本版不做**（2026-10，用户明确"不需要"）。原「有源蜂鸣器提示音」整条功能本版移除：
> BOM 行 `LS1` 标注"本版移除"、`drv_keys` 不再有蜂鸣器归宿（固件侧 `KEYS_ERR_NO_BUZZER` + WARN）。
> ⇒ 本版**没有**任何"需要第二个 PWM 或第二个扩展通道"的功能（背光只要 0/1）。

### 2.4 继电器驱动链（CA-DV8008 → 继电器线圈）

```
ESP32 GPIO4/5 (I²C 3.3 V)
      ↓
   CA-DV8008N（3.3 V 逻辑，I²C 0x28，单 8 位寄存器）   ← 一颗同时解决「引脚不够」与「驱动能力不够」
      ↓ OC1–OC6（低边灌电流，40 mA/只）
   继电器 K1–K6 线圈（HK4100F-DC5V-SHG，5 V / 125 Ω / 40 mA）
      ↓ 线圈另一端 → +5V（MP2315 降压轨）
   ✅ CA-DV8008 的 **COM 引脚必须接 +5V**（内部续流二极管共阴）
```

**元件数**：CA-DV8008N ×1 = **1 颗**，替代原「TCA9535 + ULN2003A」（2 颗）与更早的「6 个 MOSFET + 6 个续流二极管 + 6 个栅极电阻 + 6 个下拉电阻」。

**校核**：CA-DV8008 单通道 500 mA（八通道同开 250 mA），本机 40 mA（余量 6 倍以上）；输出耐压 50 V ≫ 5 V；通道压降（R_ds(on) 典型 <1 Ω）下线圈得 ≈4.9 V = 98% 额定（> 75% 吸合阈值 ✅，且 ≤130% 上限 ✅）。

🔴 **线圈只许接 `+5V`，严禁接 `VCC`**：`VCC` 是 2S 电池原压 6.0–8.4 V，而 5 V 线圈的上限是 130% 额定 = **6.5 V** ⇒ 误接 VCC 将达 **148 %–168 %** 额定功耗，超规发热（不会立刻烧毁，但绝缘老化、寿命骤降）。J17 因此**不引 VCC**（只引 +5V / +3V3_DIG）。

**🔴 OC7 / OC8 与蜂鸣器（2026-10-11 定案）**：

| 项 | 定案 | 说明 |
|----|------|------|
| **OC7 / OC8** | **保持空闲、不预接** | 用户明确要求"不要动，空着"。🔴 **硬件不接任何负载**；🔴 **固件点不到** —— 驱动位掩码只裁到 OC1–OC6（`0x3F`），OC7/OC8 **不得**出现在任何配置/写入路径里（"一个通道只有一个所有者"）。将来要用，按 §6 走变更登记 |
| **LCD 背光** | ✅ **走 GPIO21**（0/1，经低边 MOS + 100 kΩ 栅极下拉） | **不再借扩展器**（原候选"另加一颗 CA-DV8008 `0x29`"已取消），详见 §2.3 |
| **蜂鸣器** | ❌ **本版不做** | 2026-10，用户明确"不需要"。BOM 行 `LS1` 标注"本版移除"；`drv_keys` 不再有归宿（固件侧 `KEYS_ERR_NO_BUZZER` + WARN） |

### 2.5 功放驱动与 CW 键控

```
Si5351（3.3 V CMOS 方波）
      ↓
SN74ACT244PWR（5 V 供电，TTL 输入阈值 → 3.3 V 可直驱）
      ↓ ±24 mA，0–5 V 方波
MOS 栅极（Class-E 开关）
```

**CW 键控 = Si5351 使能命令**（I²C 写 `CLKx_CONTROL` 的 `CLKx_DIS` 位）：

> 🔴 **硬件侧没有"键控线"**（2026-10-17 明确写入契约）：`PA_EN` / `CW_KEY` 在网表里**都没有网络** ——
> 244 的 `1OE`/`2OE` 属**本地硬连、不经连接器**；键控点在 **RF 源**：
> **Si5351 输出使能**（I²C 寄存器 **`0x03` bit0 `CLK0_OEB`**），网表网络名 **`CW_KEY_SRC`**。
> ⇒ 做线束/排针时**不得**为键控预留引脚；若将来要改成 MCU 直接键控，必须先改本节契约、新增网络并重跑网表。

| 优点 | 说明 |
|------|------|
| **不占 GPIO** | 释放一个引脚给 EC11/ADC |
| **无插入损耗、无开关损耗** | 键控点在 RF 源，**不在射频通路也不在主供电通路** |
| **无静态电流损耗** | Class-E 无驱动时管子截止（这点与线性功放不同） |
| **PLL 保持锁定** | 重新使能是 µs 级，不丢点 |

🔴 **硬件强制要求**：

| # | 要求 | 不做的后果 |
|---|------|-----------|
| 1 | **244 输入侧加 10 kΩ 下拉到 GND** | Si5351 停振时 CMOS 输入悬空 → 244 振荡 → **PA 自激发射** |
| 2 | **MOS 栅极加下拉电阻** | 保证 OE/停振时 MOS 可靠截止 |
| 3 | 244 每个 Vcc 引脚 **100 nF 去耦**；**未用输入接固定电平** | 数据手册常规要求 |
| 4 | 244 由 **5 V** 供电 | ACT 系列 4.5–5.5 V；输入 TTL 阈值 |

> 📌 ~~功放**功率控制**那一路（GPIO12 → 升压模块 FB）的上电窗口、固件所有权划分~~ → ❌ **2026-10-11 作废（无升压）**；
> 且 **GPIO12 去向已定案 = 示波器打点**（§2.2、§2.10.2、§7 #7a **已关闭**）。
> 🔴 **注意**：GPIO12 改作打点后，**功放不再有任何"调功"手段** —— 现行口径是
> "**功放恒定按 7.4 V 标称定点输出、不做降额**"（§7 #7b/#7c；🔴 2026-10-17 用户裁定设计点统一 7.4 V），
> 只由 `ADC_FWD` **如实上报实测功率**。

**软件约束**：键控经 I²C，与 CA-DV8008N（ATU 继电器驱动）共享总线。实测单次事务 ~60 µs，占 12 WPM 点长（100 ms）的 **0.06%**。要求：键控任务**最高优先级** + FreeRTOS 互斥量（自带优先级继承）+ **绝不在发报期间做长 I²C 突发**（ATU 调谐须在非发射态；固件侧对应 `si5351_key_on()` / `si5351_key_off()` / `si5351_output_enable()`）。

### 2.6 ⚠️ strapping 引脚的用法（GPIO2 / GPIO8 / GPIO9）

> **本板 strapping 脚共 3 个：GPIO2、GPIO8、GPIO9（BOOT）。**
> 🔴 **2026-10-11 更新：EC11 A 已迁离 GPIO2（`EC11_A` → GPIO20）**，本节讨论对象变为
> **GPIO8（仍作 `EC11_B`）** 与 **GPIO2（已释放为 ADC1_CH2）**；GPIO9 见 §2.2 末行 ——
> 它是 BOOT 按键，**上电前不可下拉**，因此**不可改作任何其他用途**。

**核心判据**：能放 strapping 引脚的信号，必须在**上电瞬间天然为高**。

| 信号 | 上电电平 | 能否放 strapping |
|------|---------|-----------------|
| **EC11 B**（带上拉，仍在 GPIO8） | **高**（仅旋转时拉低） | ✅ **本方案采用**（仅剩 B 相在 strapping 脚上） |
| **EC11 A**（带上拉，**已迁 GPIO20**） | **高**（仅旋转时拉低） | ✅ **已撤出 strapping 脚** ⇒ 不再参与启动模式判决 |
| **GPIO9 的 BOOT 按键** | 高（外部上拉），**按下为低** | ⚠️ **本来就是 strapping 脚，只能在启动后使用** |
| I²C（空闲被上拉） | 高（仅传输时拉低） | ⚠️ 可以，但复位瞬间若总线被占则危险 |
| **ADC_FWD / REV** | **0 V**（无射频，二极管截止） | ❌ **不行** |
| **ADC_VBAT 分压** | 1.74–2.46 V（随电池变化） | ❌ **不行** |
| **ADC1_CH2（GPIO2）若接分压器** | 随被测电压 | ❌ **不行**：分压器输出无法保证上电为高（原约束随 EC11 迁走而**有条件的**解除，见下） |
| **LEDC 输出（如原功放功率 PWM）** | 固件上电置 **0**（低压 = 低功率档） | ❌ **不行**：0 V 直接判为低 |

**为什么检波器不能放**：无射频时输出 0 V → 判为低 → 启动异常。若用上拉救，上拉阻值被 ADC 源阻抗要求（<10 kΩ）卡死（需 ≤3.3 kΩ，持续 1 mA），且**并联在检波器负载上会破坏 SWR 标定**；改用交流耦合加偏置则动态范围只剩 0.58 V，不够测量。

**本方案的实际风险与缓解**：

| 项 | 说明 |
|----|------|
| 风险 | **在「正在旋转旋钮」的同时上电/复位** → strapping 判为低 → 启动模式异常 |
| 🔴 **2026-10-11 风险变更** | **`EC11_A` 迁离 GPIO2 后，本风险「只消除一半」** —— A 相已不在 strapping 脚上（GPIO20 非 strapping，随便转都不影响启动模式），**但 B 相仍留在 GPIO8（strapping）** ⇒ 只要"旋转时上电"且恰好压在 B 相的拉低相位上，**启动模式异常依旧可能发生** |
| 缓解 1 | **EC11 B（GPIO8）加 10 kΩ 上拉**（编码器本就需要，且恰好满足 strapping 要求）——🔴 **本条缓解必须保留**（A 相迁走后它成为唯一被 strapping 约束的那一相）；GPIO20 的 `EC11_A` **同样保留 10 kΩ 上拉**（编码器电气需要，与 strapping 无关） |
| 缓解 2 | 启动画面提示「上电时请勿转动旋钮」——🔴 **保留**（B 相仍在 GPIO8） |
| 缓解 3 | 启动后确认状态；异常可由看门狗复位重试——🔴 **保留** |
| 🔴 **彻底消除的办法与代价** | "彻底消除需把 B 也搬走，但那要占用 **GPIO21 或 GPIO12**"：`EC11_B` 必须落在一个**真正的普通 GPIO**上 —— 本版可用的非 strapping 脚只剩 **GPIO12（已定案为示波器打点）** 与 **GPIO21（已定案为 LCD 背光）**，两者都已有归属；**GPIO20 已给 `EC11_A`**。⇒ **本版不做此迁移**（代价是让出示波器打点或背光），故"旋转时上电"的风险**本版如实保留一半** |
| 📌 GPIO2 的新约束 | GPIO2 **仍是 strapping 脚**：它作为 **ADC1_CH2** 使用时，**"不得接分压器"这条约束并未无条件消失** —— 消失的是"EC11 旋转会拉低它"这一条；**若真要接分压器/传感器，仍需复核"上电瞬间该脚是否为高"**（分压器随被测电压变化 ⇒ 大概率 ❌，见上表） |

### 2.6.1 板载 LED 已拆除

**本设计已拆除板载 LED D4（GPIO12）与 D5（GPIO13）**，理由：

| LED | 挂载 GPIO | 保留的问题 |
|-----|----------|-----------|
| **D5** | **GPIO13** | GPIO13 用作 `EC11_SW` 输入，常态被上拉为高 → **D5 持续点亮约 1.3 mA**——是 MCU 深睡电流（~5 µA）的 260 倍，约 31 mAh/天，会主导电池待机预算 |
| **D4** | **GPIO12** | ~~GPIO12 输出功放功率 PWM → **D4 随之闪烁**~~ → **2026-10-11 更新**：GPIO12 已改作**示波器打点**（`BOARD_SCOPE_TP`），**不再是 PWM 输出**；D4 仍**保持拆除**（打点脚要的是干净的回转沿，灯只会加载并拖慢边沿） |

**状态指示改由 ST7567 液晶承担**（128×64 足够显示台号/频率/模式/功率/SWR/电池）。
如需外部状态灯，**挂 TCA9535 的空闲位即可，不占 GPIO**。

> 拆 LED 后 GPIO12、GPIO13 均成为**完全干净的引脚**，前文中的 LED 相关注意事项随之失效。

### 2.6.2 ⚠️ GPIO12/13 与 Flash 模式（DIO / QIO）

GPIO12=SPIHD、GPIO13=SPIWP。**本板 flash 的 HD/WP 未接到 ESP32-C3**，所以：

| flash 模式 | GPIO12、GPIO13 归属 | 后果 |
|-----------|-------------------|------|
| **DIO（本方案，强制）** | 普通 GPIO，归 BSP 使用 | ✅ 正常工作 |
| **QIO（禁止）** | MSPI 控制器驱动 SPIHD / SPIWP | 🔴 `SCOPE_TP`（GPIO12）与 `EC11_SW` **立即失效**，且**板子上电无法启动** |

ESP-IDF 的 `esp_mspi_pin_reserve()` **不看 flash 模式**，一律把 CLK/MISO/MOSI/CS0/HD/WP
登记为保留脚，因此 `gpio_config()` 会对 GPIO12/13 打 `conflict found for GPIO[n]` 警告。
该警告**只是簿记冲突、不影响功能**（ESP-IDF 源码注释原文：*"Right now, we just give a warning."*）；
固件用公开 API `gpio_reset_pin()` 显式解除保留后再配置，警告即消失。

**已实测**（见 [docs/17](17-gpio-allocation-audit.md) 附录 A）：
`mode:DIO` / `SPI Mode : DIO` / `flash io: dio` 三重确认。
（旧版固件曾在 `bsp_board` 初始化时打印 `EC11_SW(GPIO13) readback=1` 作为旁证；
2026-09-26 的所有权重构后 `bsp_board` 不再配置 GPIO13，该自检**移到 `drv_ec11` 自己的
初始化日志**中，见 §2.10。）

🔴 **纪律要求**：`CONFIG_ESPTOOLPY_FLASHMODE_DIO=y` 不得被删除或覆盖。
建议在 sdkconfig 附注释警告块，并**在构建脚本中加断言**（非 DIO 即构建失败）。

### 2.7 电池电压分压器（GPIO3）

**为什么从 GPIO2 移到 GPIO3**：GPIO2 是 strapping 引脚，而分压器输出随电池电压变化——欠电时 6.0 V × 0.29 = **1.74 V**，低于 strapping 判决阈值（≈0.75×VDD = 2.48 V）→ **电池电量偏低时设备无法启动**。GPIO3 是 ADC1_CH3 且非 strapping，无此约束。

> 🔴 **2026-10-11 补充（本次分配变更的连带影响）**：`EC11_A` 迁离 GPIO2 后，GPIO2 被**释放为 ADC1_CH2**（第 4 路模拟输入，§2.1/§2.2），
> 因此原文「空闲的 ADC1 通道只剩 GPIO2 与 GPIO4，两者都被占用」的**结论已不再成立**：
> 模拟输入的可用余量从 **0 恢复到 1（GPIO2/CH2）**。
> ⚠️ **但"电池分压器要不要挪回 GPIO2"这个问题的答案仍然是不挪**，理由与本节原文一致：
> **GPIO2 本身依旧是 strapping 脚**（上电须为高），而分压器输出随机型电量在 1.74–2.46 V 之间浮动 ⇒
> **只是"EC11 旋转拉低它"这一条风险消失了，分压器自身的上电电平问题一条都没少**。
> ⇒ 本节的 22k/9.1k（现行 30k/9.1k，见 §7 #7d）分压器**继续留在 GPIO3**；GPIO2（CH2）留给**上电电平可控**的模拟输入（温度/电流等，届时按 §2.6 复核上电电平）。

```
VBAT ──[R1 22k]──┬──[R2 9.1k]── GND
                  │
                  ├──[R3 1k]── GPIO3
                  │
                [C 0.1µF] ── GND
```

| 参数 | 值 | 校核 |
|------|-----|------|
| 8.4 V 时输出 | **2.46 V** | ✅ < 2.5 V（11 dB 衰减量程） |
| 6.0 V 时输出 | **1.76 V** | ✅ 在量程内 |
| 源阻抗 | `R3 + (22k ∥ 9.1k)` = 1000 + 6437 = **7.4 kΩ** | ✅ < 10 kΩ（ESP32-C3 ADC 要求） |
| 静态电流 | **270 µA** | 2000 mAh 约 309 天（已接受，不加门控） |
| 滤波 | 0.1 µF → fc ≈ 245 Hz | ✅ 抑制噪声 |

> 🔴 **2026-10-11 待决（12 V 兼容）**：若确认输入级要"兼容 12 V"，上表 `R1 = 22k` 需改 **30k**
> ⇒ 比值 `R2/(R1+R2)` 0.2926 → **0.2327**、满量程 11.3 V → **14.18 V**、12 V 读数 **2.79 V** ✅、
> 源阻抗 7.98 kΩ（仍 <10 kΩ ✅）、静态电流 215 µA（8.4 V；现行 270 µA）。**未定前不要改板**；改后下表阈值列需按新比值重算
> （6.8 V → 1.58 V、6.0 V → 1.40 V）。详见 §7 #7d 与 [docs/04 §3.7.2](04-hardware-architecture.md)。

**固件判据（2026-10-11 定案 · 2S 锂电口径）**

| 状态 | VCC | ADC 折算（ratio 0.2926） | 固件动作 |
|---|---|---|---|
| 满电 | 8.40 V | ≈2.46 V | — |
| 标称 | 7.40 V | ≈2.17 V | — |
| **低电告警** | **≤ 6.80 V** | ≈1.99 V | 界面/日志告警；🔴 不得发起高功率发射（PA 输出此时已降至 ≈1.6 W） |
| **放电截止** | **≤ 6.00 V** | ≈1.76 V | 停发并提示充电；🔴 硬保护由 **2S BMS** 兜底，固件只做提示级（不得依赖固件截止保护电池） |
| 满量程 | 11.3 V | 3.30 V | 分压器硬件**无需改动**（罩得住 8.4 V，也罩得住 3S 铁锂 10.95 V） |

**备选阻值**：`R1 = 24k, R2 = 10k`（比值 0.294，源阻抗 `R3 + (R1∥R2)` = **8.1 kΩ**，静态 247 µA）

### 2.10 🔴 GPIO 所有权与上电安全（固件初始化契约）

> 本节是 §2.2 引脚表的**配套契约**：定义"每根脚由谁在固件里配置"以及
> "配置发生之前（上电 → 驱动 init）这段时间该脚是什么状态"。
> 引入原因是一次**所有权冲突**的实测排错，见 §2.10.1 与 §2.10.4。

#### 2.10.1 所有权分配（一根脚只有一个所有者，且只被配置一次）

| 引脚 | 功能 | 固件所有者 | 配置动作 |
|---|---|---|---|
| GPIO0 / GPIO1 / GPIO3 | ADC 前向 / 反向 / 电池 | `drv_analog` | `adc_oneshot_config_channel()` |
| **GPIO2** | **ADC1_CH2（第 4 路模拟输入，本版释放）** | `drv_analog`（**仅当该通道被启用时**） | `adc_oneshot_config_channel()`；⚠️ 该脚**仍是 strapping 脚**，启用前须按 §2.6 复核上电电平 |
| **GPIO20** | **`EC11_A`（自 GPIO2 迁来）** | `drv_ec11` | 输入 + 内部上拉（**外部 10 kΩ 上拉是强制要求**）；🔴 **GPIO20 非 strapping** ⇒ 不再有"旋转时上电"约束 |
| GPIO8 | `EC11_B`（**仍在 strapping 脚上**） | `drv_ec11` | 输入 + 内部上拉（**外部 10 kΩ 上拉是强制要求**，见 §2.6） |
| GPIO4 / GPIO5 | I²C SDA / SCL | **I²C 驱动**（总线对象归 `bsp_board`） | `i2c_new_master_bus()` 内部自行 reserve + 开漏 + 上拉 + matrix 连接 |
| GPIO6 / GPIO7 | LCD SCK / MOSI | `drv_lcd12864` | `spi_bus_initialize()` |
| GPIO9 | KEY_USER（BOOT） | `drv_keys` | 输入 + 内部上拉 |
| GPIO10 | LCD_DC | `drv_lcd12864` | `gpio_reset_pin()` → `gpio_config(输出)` |
| **GPIO21** | **`LCD_BL`（背光使能，0/1，非 PWM）** | **`drv_lcd12864`** | `gpio_config(输出 + 内部下拉)` → **上电即置 0**；🔴 **"上电默认低 = 关"由硬件 100 kΩ 栅极下拉保证**（§2.3/§2.4），固件只是不主动点亮 |
| **GPIO12** | **`SCOPE_TP`（示波器打点）** | **`bsp_board`（独占；调试用途）** | `gpio_reset_pin()` → `gpio_config(输出)`，**上电即置 0**；🔴 **不接任何控制对象** ⇒ 原"上电窗口"安全论证不再需要（§2.10.2 已作废） |
| GPIO13 | EC11_SW | `drv_ec11` | 输入 + 内部上拉（`bsp_board` 只撤销 MSPI 保留位） |

> 🔴 **CA-DV8008 的 OC7 / OC8 不在本表内，这是刻意为之**：两通道**保持空闲、不预接**，
> 固件**不得**为其建立任何配置或写入路径（"一根脚/一个通道只有一个所有者，且只被配置一次"的推论）。
> 驱动层的位掩码只裁到 **OC1–OC6（`0x3F`）**，未点名的位按 RMW 契约保持原值 —— 见 §2.4 与 [docs/17](17-gpio-allocation-audit.md)。

**`bsp_board` 的职责被收窄为三件事**：引脚映射表、硬件版本识别、共享 I²C 总线
（总线 + 互斥量）；外加示波器打点脚 GPIO12 的初始化（§2.10.2）。

> 🔴 **"只被配置一次"是硬约束**：`gpio_config()` 在输出模式下会
> `esp_gpio_reserve()` 把该脚登记为"已保留"（`esp_driver_gpio/src/gpio.c`），
> LEDC 与 I²C 驱动同样会 `esp_gpio_reserve()`。**同一根脚被登记两次**就会打印
> `conflict found for GPIO[n]` / `GPIO n is not usable, maybe conflict with others`
> 之类的**簿记警告**。它不影响功能（源码注释原文 *"Right now, we just give a warning."*），
> 但属误导性噪音 —— 将来真出问题会被忽略。

#### 2.10.2 GPIO12（`SCOPE_TP` 示波器打点）的上电窗口 → ✅ **已由"安全议题"降级为"调试议题"**

> 🔴 **2026-10-11 状态变更（本节结论反转）**：本项目**不设升压**（原 U11 已删），且 **GPIO12 的去向已定案 = 示波器打点（`BOARD_SCOPE_TP`）**，
> 因此 **§7 #7a 关闭**。GPIO12 **不再接任何被控对象**（既不接升压 FB，也不接功放驱动使能、也不接未来 PA 轨调压）
> ⇒ 下文原有的"上电窗口必须钉低，否则功放被推向满功率"**整条安全论证不再适用**，保留作为历史依据。

~~GPIO12 接升压模块的 FB 网络：**低电平 = 最低功率**，高电平/浮空 = 有被推向满功率的风险。~~

**现行（2026-10-11）GPIO12 的初始化契约**：

| 阶段 | 谁在负责 | 该脚状态 |
|---|---|---|
| 芯片复位 → `bsp_board_init()` 之前 | 无（复位默认态） | 高阻（输出关闭、无上下拉）——**打点脚悬空无害**（无被控对象） |
| `bsp_board_init()` | **`bsp_board`（独占所有者）** | `gpio_reset_pin()` 撤销 MSPI 簿记保留 → `gpio_config(输出)` → **置 0** |
| 之后 | `bsp_board` | **仅由调试代码翻转**（打点脉冲）；🔴 **不驱动任何功率级** |

- **为什么还要由 BSP 持有**：打点脚要的是**确定的电平与干净的边沿**；由 BSP 在 init 链最早期一次性配好，
  可避免别的驱动把它当普通 IO 抢去配置（`conflict found for GPIO[12]`）。
- ⚠️ **若将来复用该脚作调压/使能（§7 #7a 的方案②复活）**：本节原有的
  "`drv_pa` 接管时必须显式关闭 `gpio_reset_pin()` 打开的内部上拉"教训**仍成立** ——
  只加下拉而不关上拉会让 FB 节点停在 ≈VDD/2 的**中间电平**，对反馈脚而言比确定的高/低更糟。
- ✅ **打点脚的"上电默认态"本身不是安全问题**：功放"上电即安全"由
  "Si5351 停振 ⇒ 无射频驱动 ⇒ Class-E 截止"保证（§2.5），与 GPIO12 无关。

#### 2.10.4 与 §2.6.2（GPIO12/13 与 Flash 模式）的关系

两件事容易混淆，此处明确区分：

| 事项 | 来源 | 处理 |
|---|---|---|
| **MSPI 簿记保留** | ESP-IDF 的 `esp_mspi_pin_reserve()` **不看 flash 模式**，一律把 HD/WP（C3 上 = GPIO12/13）登记为占用 | 由 `bsp_board` 用公开 API `gpio_reset_pin()` 撤销（GPIO13；GPIO12 由 BSP 与 `drv_pa` 各撤一次） |
| **同一脚被配置两次** | `gpio_config(输出)` / LEDC / I²C 驱动都会 `esp_gpio_reserve()` | 由**所有权契约**（§2.10.1）消除：一根脚只配一次 |

> 🔴 注意 `gpio_config()` 的 conflict 判定对**纯输入模式**同样成立
> （`reserved && input_en` 与 `reserved && !input_en` 互补 ⇒ 等价于 `reserved`），
> 所以 GPIO13 的保留位**必须由 `bsp_board` 先撤销**，否则 `drv_ec11` 配输入时
> 会重新冒出 `conflict found for GPIO[13]`。

#### 3.2.1 SWR 检测方案对比（2026-10-11 补充）

| # | 方案 | 结构 | 优点 | 缺点 | 典型用途 |
|---|---|---|---|---|---|
| **①** | **Tandem Match（本项目 ✅）** | **2× 电流变压器（1:N）共用主线 + 次级串接 + 两端各 50 Ω** | **方向性最好（>30 dB）**、宽带、频率无关（无需分压补偿）、可大功率 | 需两只**配对**变压器与配对电阻（体积/成本中） | ATU-100（N7DDC）、ARRL Handbook 定向瓦特计、多数 QRP 天调 |
| ② | Bruene 电桥 | 1 只 CT + **RC/电容分压**取电压 | 元件少、经典 | 方向性/带宽略差；**分压器需频率补偿**；共地麻烦 | 老式 SWR 表 |
| ③ | 单变压器反射计（Monimatch 型） | 1 磁环 + 2 二极管直接取样（**无终端**） | 最简最便宜 | **方向性仅 10–20 dB**、非线性、需逐台标定 | 廉价 SWR 表、CB |
| ④ | 耦合线定向耦合器 | 两条并行传输线（微带/同轴） | 宽带、精度高、功率容量大 | 需阻抗/叠层控制的 PCB；3.5 MHz 下体积大 | 商用耦合器、VNA |
| ⑤ | 电阻桥 / 惠斯登 | 4 电阻 + 检测器（天线为一臂） | 极简 | 仅低功率/窄带、有插损 | 天线噪声桥 |
| ⑥ | **有源矢量/对数检波**（**V2 备选**） | CT + 分压，或 **AD8307/AD8313 对数检波** | **可测幅相 ⇒ 直算复阻抗 R±jX**；动态范围 90 dB | 需检波 IC + 运放 + 标定，成本高 | 现代自动天调、功率计、矢网 |
| ⑦ | 双定向耦合器（DDC） | 两个耦合器 / 一体式 | 方向性好、带宽宽 | 成本/体积 | 专业功率计 |

#### 3.2.2 为什么本项目选 ① Tandem Match

1. **方向性是联锁的命门**：`SWR>3.0 禁发` 误动会打断发射、漏动会打坏 PA ⇒ 需要 ①（>25–30 dB），不能用 ③（10–20 dB）。
2. **频率无关**：① 的电压/电流取样都靠**电流变压器 + 50 Ω 终端**完成 ⇒ 不需要像 ② 那样给分压器做频率补偿。
3. **已被 ATU-100 大规模验证**（同款拓扑、同款 50 Ω 终端）。
4. **V2 备选 = ⑥**：若将来要求"**不做 64 组合搜索、直接算 L/C**"，或要求**微功率档（0.02 W）**读数精确（现二极管检波在平方律区非线性），则升级为 **AD8307 对数检波**方案；现阶段保留二极管 + 多点软件标定即可。

#### 3.2.3 逐器件作用（修正版 · 2026-10-11）

```
RF_IN ─┬─[T1 1:10]─┬─[T2 1:10]─┬─ 主线 → LC 匹配网络 → 天线
       │            │            │
   次级A端       串接点        次级B端
       │                          │
   R_term=50Ω                 R_term=50Ω
       │                          │
    D3(1N5711)+D4(HSMS-2850占位)  D1(1N5711)+D2(HSMS-2850占位)
       │                          │
   C(10n) → R(68k) → C(10n)    同左
       │                          │
   ADC_REV                    ADC_FWD        ← 极性须实测（§3.2.5）
```

| 器件 | 作用 | 关键点 |
|---|---|---|
| **T1 / T2** | 方向耦合器本体：两芯穿**同一根主线**（初级 1 匝）、次级各 **N=10 匝** | **耦合度 = 20·log₁₀(N) = 20 dB** ⇒ 与本项目"20±3 dB"口径自洽；T1 取**电流**、T2 取**电压**；FWD/REV 是**两端串接后的和/差**，**不是**单独从 T1 或 T2 出来 |
| **`R_term`（原称 R_sense）= 50 Ω / 1 W（2512）** | 次级**AC 终端负载** | 🔴 **必须 = Z₀ = 50 Ω**（桥的成立条件）；两只**必须等值**（1% 或配对），否则方向性崩塌。🔴 **旧文档写的"初值 1 kΩ"是错误值**：它既破坏桥平衡，又使 `V_det ≈ (I/N)·1k = 22 V`（2.5 W 时）⇒ 二极管导通/ADC 削顶 |
| **D1/D3（1N5711）· D2/D4（HSMS-2850 占位）** | **肖特基峰值检波** | 肖特基 `V_F` 仅 0.15–0.3 V（硅管在 QRP 下检不出）；小信号处为**平方律** ⇒ 必须多点软件标定；两管并行供实测选优 |
| **检波后 RC（新增）** | C(10 nF) → R(68 k) → C(10 nF) 两级 **C-R-C** | 见 §3.2.4 选值依据；🔴 **与 `R_term` 是两个不同角色**（终端 = AC，RC = DC/滤波） |
| **ADC 节点泄放 100 kΩ（建议）** | 给 C 定义放电通路 | 否则放电只靠 ADC 高阻输入 ⇒ 时间常数不可控 |
| **`ADC_FWD` / `ADC_REV` → GPIO0/GPIO1** | 固件算 `Γ=REV/FWD`、`SWR=(1+Γ)/(1−Γ)` | 需**功率 + SWR 双标定**（覆盖平方律区） |

**电平核对**（N=10、R=50 Ω）：2.5 W/50 Ω 时 `V_line=11.2 V` ⇒ `V_det ≈ V_line/N = **1.12 V**` ✅ 正落 ADC 好区间。
⚠️ 要更高电平应**加大 N（1:20 ⇒ 2.24 V、26 dB）或加运放**，**绝不能改终端电阻** ✗。

#### 3.2.4 检波后 RC 选值：**10 nF + 68 k + 10 nF（C0G）** ✅

| 项 | A：100 nF+68k+100 nF | **B：10 nF+68k+10 nF ✅** |

| 时间常数 τ | 6.8 ms | **0.68 ms** |
| 3.55 MHz 抑制 | −103 dB | **−83.6 dB（已足够）** |
| 残余纹波 vs ADC 1 LSB(0.8 mV) | 0.02 mV | **0.17 mV ✅ 仍低于 LSB** |
| 64 组合调谐耗时 | 3–5 s（"首次调谐 <5 s"无余量 ✗） | **0.5–1 s ✅** |
| CW 点长 60 ms 跟踪 | 滞后 7–10 ms | **~1 ms ✅** |
| 电容选型 | 100 nF C0G 难得/体积大 | **10 nF C0G 常见 ✅** |

**选 B 的理由**：RF 抑制两者都远超需求（不是瓶颈）⇒ 不应为"更狠的滤波"牺牲速度；**平滑交给固件数字平均**（可随时调、可按功率档切换），硬件留带宽 ✓。

#### 3.2.5 FWD/REV 极性实测（投板前必做）

**为什么必须实测**：FWD/REV 取决于**绕组相位与穿芯方向**，理论无法替他判定。

```
① RF_OUT（天线口）接 50 Ω 假负载（≥5 W）；RF_IN 接发射机/信号源   ← 🔴 不可用真天线判极性
② 发等幅载波 1–2 W，用万用表 DC 档量 ADC_FWD / ADC_REV 两点
③ 判据：接 50 Ω 假负载时**读数明显大的一端 = FWD**；另一端应 ≤ 1/17.8（−25 dB ⇒ 方向性 >25 dB）
④ 若反了 ⇒ 把图上与固件中的 FWD/REV 标签**对调**即可（无需重绕）
⑤ 复核：换开路/短路 ⇒ 两端读数应接近相等（≈全反射参考点，用于 SWR 标定）
⑥ 记录 0.5 / 1 / 2 / 2.5 W 各点 FWD 读数 ⇒ 建功率标定表
```

|----|------|---------|------|

### 4.2 控制与电源互联

必须定义（**待硬件设计后冻结**）：

> 🔴 **2026-10-17 定案（PA 键控契约）：`PA_EN` / `CW_KEY` / `PA_PWR_PWM` 三个信号都不存在、也不该引出。**
> **PA 键控不使用独立 MCU 输出**；**PA 由 Si5351 CLK0 输出使能**（I²C 寄存器 **`0x03` bit0 `CLK0_OEB`**，

> | 幽灵信号 | 为什么不需要 / 为什么网表里没有 |

> | `PA_EN` | 网表**无此网络**。SN74ACT244 的 `1OE`/`2OE` 属**本地硬连、不经连接器**；本设计中"功放使能" = "CLK0 有输出"，故无独立使能线 |
> | `CW_KEY` | 键控点在 **RF 源**（Si5351 输出使能），既不在射频通路、也不在主供电通路 ⇒ **没有键控走线**；网表只有 `CW_KEY_SRC`（I²C 写 `CLKx_DIS`） |

| 信号 | 电平 | 方向 | 说明 |
|------|------|------|------|
| `FWD_DET` | 0–3.3 V | SWR → MCU(ADC) | 前向检波 |

## 6. 变更流程

任何涉及本契约的变更，必须按以下流程：

```
1. 修改 docs/05-hw-sw-interface-contract.md（提出变更，标注状态为「提议」）
2. 硬件方确认：原理图/PCB/BOM 影响评估
3. 软件方确认：bsp_board / 相关组件影响评估
4. 双方评审通过 → 本文件状态改为「冻结」
5. 同步提交：原理图变更 + bsp_board 变更（同一 PR 或关联 PR）
6. 更新 CHANGELOG.md
```

**禁止事项**

| ❌ 禁止 | 原因 |
|--------|------|
| 在组件中硬编码 GPIO 号 | 破坏 `bsp_board` 单一来源 |
| **同一根脚被两个组件各自 `gpio_config()` 一次** | 触发 ESP-IDF 簿记冲突警告（误导性噪音），且所有权不明 —— 见 §2.10.1 |
| **`bsp_board` 对外设引脚做方向/上下拉配置** | 违反 §2.10.1 所有权契约（唯一例外：GPIO12 上电安全） |
| 硬件改引脚但不改本文件 | 软件将驱动错误引脚 |
| 固件与中控各自定义帧结构 | 协议漂移，无法互通 |
| 把密钥硬编码进源码 | 安全红线 |

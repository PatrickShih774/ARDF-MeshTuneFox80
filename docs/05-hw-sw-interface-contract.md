## 1. GPIO 资源约束分析

### 1.1 ESP32-C3 可用 GPIO

ESP32-C3 标称 22 个 GPIO，但实际可用受限：

| 引脚范围 | 状态 | 说明 |
|---------|------|------|
| GPIO0 – GPIO10 | **11 个可用** | GPIO0–4 为 ADC1_CH0–CH4；GPIO2/GPIO8/GPIO9 为 strapping 引脚 |
| GPIO11 – GPIO17 | **不可用** | 内部连接 SPI Flash / PSRAM |
| GPIO18 – GPIO19 | **2 个可用** | 原生 USB D−/D+ |
| GPIO20 – GPIO21 | **2 个可用** | UART0 TX/RX |
| **合计可用** | **15 个** | — |

**ADC 约束**

| 项 | 说明 |
|----|------|
| ADC1 通道 | GPIO0–GPIO4（5 通道），**可在 WiFi 工作期间使用** |
| ADC2 通道 | GPIO5，**与 WiFi 冲突，本项目不使用** |
| 结论 | → 所有模拟量必须落在 **GPIO0–GPIO4** 上，最多 5 路 |

### 1.2 需求侧引脚统计

| 类别 | 需求 | 数量 |
|------|------|------|
| 模拟输入 | 前向检波、反向检波、电池电压、功放 NTC、（备用：电源电流） | 4–5 |
| I2C | Si5351 + TCA9535 + LCD | 2 |
| 数字输出（慢速） | 继电器 K1–K6、蜂鸣器、PA_EN、LCD RST、LCD 背光 | 11 |
| 数字输入（慢速） | EC11 A/B/SW、按键 ×2 | 5 |
| 快速数字 | CW 键控、功放功率 PWM | 2 |
| 调试 | UART0 或原生 USB | 2 |
| **合计** | — | **26–27** |

**结论**：需求（26–27）远超可用 GPIO（15），**必须使用 I/O 扩展器**，且显示接口必须走少引脚方案。

### 1.3 分配决策

见 [ADR-0004](adr/ADR-0004-lcd12864-on-shared-i2c.md)：

- **LCD 走 I2C**（ST7567 支持 I2C 模式），与 Si5351、TCA9535 共享总线 → 释放 4 个 GPIO。
- **全部慢速 IO 挂 TCA9535**（16 位 I2C 扩展器）→ 释放 11 个 GPIO。
- **稀缺 GPIO 留给**：ADC（GPIO0–4）、CW 键控（GPIO7）、功放功率 PWM（GPIO8）。

**不占用 GPIO 的连接**：

| 信号 | 接法 | 理由 |
|------|------|------|
| **ST7567 `CS`** | **接 GND** | LCD 是 SPI2 上**唯一从机**，片选常有效 → 省 1 脚 |
| **ST7567 `RST`** | **与板载复位引脚共用** | 上电复位即可，省 1 脚与 RC 电路 |
| **CW 键控** | **Si5351 使能命令**（I²C 写 `CLKx_DIS`） | 完全不占 GPIO，见 §2.5 |

### 2.3 TCA9535 I²C 扩展器（16 位，用 8）

**器件**：TCA9535，I²C 地址 `0x20`。

| 位 | 功能名 | 方向 | 说明 |
|----|--------|------|------|
| P0.0 – P0.5 | `IOEXP_RELAY_K1` … `K6` | O | **ATU 6 个继电器**，经 **ULN2003A** 驱动 |
| P1.0 | `IOEXP_EC11_SW` | I | **EC11-M 的按压开关**（该型号为「旋转 + 按下」一体） |
| P1.1 | `IOEXP_LCD_BL` | O | **ST7567 背光开关**（经晶体管驱动） |
| P1.2 – P1.7、P0.6 – P0.7 | `IOEXP_SPARE` | — | **预留 8 位**（蜂鸣器、散热风扇、天线泄放等） |

**背光驱动**：

```
TCA9535 P1.1 ──[R 1k]── 2N7002 栅极
2N7002 漏极 ── 背光 LED 阳极串（经限流电阻）
2N7002 源极 ── GND
🔴 栅极加 10 kΩ 下拉到 GND —— TCA9535 上电时 I/O 为**输入高阻**，
   不加下拉则背光状态不定（可能上电即常亮，耗电且刺眼）
```

> ⚠️ **背光经扩展器只能开/关**——TCA9535 无法产生硬件 PWM。
> 若日后需要调光，**GPIO13（当前预留）可用 LEDC**（本板限 4 路 LEDC，功放功率已占 1 路）。

### 2.4 继电器驱动链（TCA9535 → ULN2003 → 继电器）

```
ESP32 GPIO4/5 (I²C 3.3 V)
      ↓
   TCA9535（3.3 V，16 位扩展器）      ← 解决「引脚不够」
      ↓ P0.0–P0.5（3.3 V 并行，6 根）
   ULN2003A（7 路达林顿，用 6 路）    ← 解决「驱动能力/电压不够」
      ↓ OUT1–OUT6
   继电器 K1–K6 线圈（12 V，16.7 mA/只）
      ↓
   ✅ ULN2003A 的 **COM 引脚必须接 +12 V**（内部续流二极管靠它生效）
```

**元件数**：TCA9535 ×1 + ULN2003A ×1 = **2 颗**，替代了「6 个 MOSFET + 6 个续流二极管 + 6 个栅极电阻 + 6 个下拉电阻」。

**校核**：ULN2003A 500 mA/路，本机 16.7 mA（余量 30 倍）；V_CE(sat) ≈ 0.9 V → 线圈得 11.1 V = 92%（> 75% 吸合阈值 ✅）。

### 2.5 功放驱动与 CW 键控

```
Si5351（3.3 V CMOS 方波）
      ↓
SN74ACT244PWR（5 V 供电，TTL 输入阈值 → 3.3 V 可直驱）
      ↓ ±24 mA，0–5 V 方波
MOS 栅极（Class-E 开关）
```

**CW 键控 = Si5351 使能命令**（I²C 写 `CLKx_CONTROL` 的 `CLKx_DIS` 位）：

| 优点 | 说明 |
|------|------|
| **不占 GPIO** | 释放一个引脚给 EC11/ADC |
| **无插入损耗、无开关损耗** | 键控点在 RF 源，**不在射频通路也不在主供电通路** |
| **无静态电流损耗** | Class-E 无驱动时管子截止（这点与线性功放不同） |
| **PLL 保持锁定** | 重新使能是 µs 级，不丢点 |

🔴 **硬件强制要求**：

| # | 要求 | 不做的后果 |
|---|------|-----------|
| 1 | **244 输入侧加 10 kΩ 下拉到 GND** | Si5351 停振时 CMOS 输入悬空 → 244 振荡 → **PA 自激发射** |
| 2 | **MOS 栅极加下拉电阻** | 保证 OE/停振时 MOS 可靠截止 |
| 3 | 244 每个 Vcc 引脚 **100 nF 去耦**；**未用输入接固定电平** | 数据手册常规要求 |
| 4 | 244 由 **5 V** 供电 | ACT 系列 4.5–5.5 V；输入 TTL 阈值 |

**软件约束**：键控经 I²C，与 TCA9535 共享总线。实测单次事务 ~60 µs，占 12 WPM 点长（100 ms）的 **0.06%**。要求：键控任务**最高优先级** + FreeRTOS 互斥量（自带优先级继承）+ **绝不在发报期间做长 I²C 突发**（ATU 调谐须在非发射态）。

### 2.6 ⚠️ strapping 引脚的用法（GPIO2 / GPIO8）

**核心判据**：能放 strapping 引脚的信号，必须在**上电瞬间天然为高**。

| 信号 | 上电电平 | 能否放 strapping |
|------|---------|-----------------|
| **EC11 A/B**（带上拉） | **高**（仅旋转时拉低） | ✅ **本方案采用** |
| I²C（空闲被上拉） | 高（仅传输时拉低） | ⚠️ 可以，但复位瞬间若总线被占则危险 |
| **ADC_FWD / REV** | **0 V**（无射频，二极管截止） | ❌ **不行** |
| **ADC_VBAT 分压** | 1.74–2.46 V（随电池变化） | ❌ **不行** |

**为什么检波器不能放**：无射频时输出 0 V → 判为低 → 启动异常。若用上拉救，上拉阻值被 ADC 源阻抗要求（<10 kΩ）卡死（需 ≤3.3 kΩ，持续 1 mA），且**并联在检波器负载上会破坏 SWR 标定**；改用交流耦合加偏置则动态范围只剩 0.58 V，不够测量。

**本方案的实际风险与缓解**：

| 项 | 说明 |
|----|------|
| 风险 | **在「正在旋转旋钮」的同时上电/复位** → strapping 判为低 → 启动模式异常 |
| 概率 | 低（需人手动作与上电瞬间重合） |
| 缓解 1 | EC11 A/B 各加 **10 kΩ 上拉**（编码器本就需要，且恰好满足 strapping 要求） |
| 缓解 2 | 启动画面提示「上电时请勿转动旋钮」 |
| 缓解 3 | 启动后确认状态；异常可由看门狗复位重试 |

### 2.7 电池电压分压器（GPIO3）

**为什么从 GPIO2 移到 GPIO3**：GPIO2 是 strapping 引脚，而分压器输出随电池电压变化——欠电时 6.0 V × 0.29 = **1.74 V**，低于 strapping 判决阈值（≈0.75×VDD = 2.48 V）→ **电池电量偏低时设备无法启动**。GPIO3 是 ADC1_CH3 且非 strapping，无此约束。

```
VBAT ──[R1 22k]──┬──[R2 9.1k]── GND
                  │
                  ├──[R3 1k]── GPIO3
                  │
                [C 0.1µF] ── GND
```

| 参数 | 值 | 校核 |
|------|-----|------|
| 8.4 V 时输出 | **2.46 V** | ✅ < 2.5 V（11 dB 衰减量程） |
| 6.0 V 时输出 | **1.76 V** | ✅ 在量程内 |
| 源阻抗 | 22k ∥ 9.1k = **6.5 kΩ** | ✅ < 10 kΩ（ESP32-C3 ADC 要求） |
| 静态电流 | **270 µA** | 2000 mAh 约 309 天（已接受，不加门控） |
| 滤波 | 0.1 µF → fc ≈ 245 Hz | ✅ 抑制噪声 |

**备选阻值**：`R1 = 24k, R2 = 10k`（比值 0.294，源阻抗 7.1 kΩ，静态 247 µA）

> **唯一事实来源**：`software/protocol/`（规划中，待创建）。协议一旦开始编写，固件的 `comm_console`、`net_espnow` 与中控软件都必须使用由 `software/protocol/generated/`（规划中，待创建）生成的代码，**禁止各自手写帧结构**。

## 6. 变更流程

任何涉及本契约的变更，必须按以下流程：

```
1. 修改 docs/05-hw-sw-interface-contract.md（提出变更，标注状态为「提议」）
2. 硬件方确认：原理图/PCB/BOM 影响评估
3. 软件方确认：bsp_board / 相关组件影响评估
4. 双方评审通过 → 本文件状态改为「冻结」
5. 同步提交：原理图变更 + bsp_board 变更（同一 PR 或关联 PR）
6. 更新 CHANGELOG.md
```

**禁止事项**

| ❌ 禁止 | 原因 |
|--------|------|
| 在组件中硬编码 GPIO 号 | 破坏 `bsp_board` 单一来源 |
| 硬件改引脚但不改本文件 | 软件将驱动错误引脚 |
| 固件与中控各自定义帧结构 | 协议漂移，无法互通 |
| 把密钥硬编码进源码 | 安全红线 |

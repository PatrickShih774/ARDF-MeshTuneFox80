### 1.3 方法

1. **交叉核对**：公开仓文档 ↔ 私有仓 `board_pins.h` ↔ 私有仓 `bsp_board.h` 枚举，三处逐项对齐。
2. **回溯一手来源**：芯片事实一律回到 ESP-IDF v6.1 源码行号或 ESP32-C3 数据手册章节，不采信任何文档里的自述。
3. **实测证据**：以真机启动日志为准（附录 A），它同时验证了「DIO 生效」与「GPIO12/13 真的可用」。
4. **可扩展性判据**（本审计的核心尺度）：

   | 判据 | 能否挂 TCA9535 | 理由 |
   |------|---------------|------|
   | ADC 采样 | ❌ | TCA9535 只有数字 I/O，无 ADC |
   | 硬件 PWM / 频率 | ❌ | TCA9535 无定时器/PWM，只能静态开/关 |
   | **软 PWM（开/关频率足够低）** | ⚠️ 理论可以 | 但 I²C 写一次 ≈ 60–180 µs，占空比受总线负载限制 |
   | I²C 本体 | ❌ | 自举问题：扩展器不能扩展出它自己的总线 |
   | SPI 时钟/数据 | ❌ | TCA9535 无法产生 MHz 级串行时序 |
   | **每字节翻转的控制线（LCD_DC）** | ❌ 实际不可行 | 见 §5.4.4 备选 D 的定量核算 |
   | 中断输入 | ⚠️ 需占用 1 个真引脚承载 INT | 见 §5.5 的关键约束 |
   | 慢速数字 I/O（继电器、背光、按键、状态灯、风扇） | ✅ | 静态电平，人眼/机械时间尺度 |

## 3. 「不可扩展功能必须用真引脚」原则的核查

### 3.1 ADC —— ✅ 完全满足

| 需求 | 引脚 | ADC 归属 | 是否 WiFi 可用 | 结论 |
|------|------|---------|---------------|------|
| 前向检波 | GPIO0 | ADC1_CH0 | ✅ | ✅ |
| 反向检波 | GPIO1 | ADC1_CH1 | ✅ | ✅ |
| 电池电压 | GPIO3 | ADC1_CH3 | ✅ | ✅ |

- 三路模拟量**全在 ADC1**，ADC1 是唯一出厂标定的 ADC（数据手册 §5.6 表 5-6）。
- 未占用 GPIO5（唯一 ADC2 通道）作为模拟输入 —— 正确，因为 ADC2 **未标定**，且**部分芯片版本根本不可用**。
- 空闲的 ADC1 通道只剩 **GPIO2（CH2）** 与 **GPIO4（CH4）**，两者都已被 EC11_A / I²C_SDA 占用。
  → **模拟量扩无可扩**：这是"必须用真引脚"原则最硬的约束，也是本审计认为
  **不应把任何 ADC 通道让给数字功能**的根本理由。

### 3.2 PWM —— ✅ 满足（但文档说明有误）

- 功放功率档位走 **LEDC**，可映射到**任意** GPIO（数据手册 §4.2.1.7）→ 该功能**不绑定引脚**，属"可自由搬家"。
- 当前落在 GPIO12（属 MSPI 簿记保留脚）——**功能上正确，风险上不必**，见 §5。
- ⚠️ 本项目**没有第二个 PWM 需求**（无蜂鸣器调音、无背光调光）。若将来需要：
  LEDC 共 6 路通道，远未用尽。

### 3.3 I²C —— ✅ 不可扩展，必须真引脚

I²C 总线本身不能被 I²C 扩展器扩展（自举悖论）。SDA/SCL 只能占真引脚 → 无优化空间。

### 3.4 SPI —— ✅ 不可扩展，必须真引脚

ST7567 的 SCK/MOSI 需要 SPI2 的硬件时序（MHz 级），TCA9535 无法产生。已通过
**`CS` 接地 + `RST` 与板复位共用**省下 2 脚（ADR-0008 §3.1），这是该原则下已做足的优化。

### 3.5 中断 —— ⚠️ 需注意：TCA9535 的 INT **必须占用 1 个真引脚**

这是本审计的**关键发现之一**，且任务描述中的推演 2 未把它计入：

> 把 EC11 A/B 移到 TCA9535 后，若仍希望"中断驱动"响应，则必须把 TCA9535 的 `INT`
> 输出引回一个**真 GPIO**。而这个引脚只能来自"刚刚腾出来的 GPIO2/8/13"。

因此收益需要**先扣掉 1 个引脚**才能算净值（详见 §5.3 与 §5.5）。

## 5. 优化方案对比

### 5.0 三个方案的共同前提

- PCB **尚未打样** → 现在改方案的成本仅为文档与固件改动；投板后即为改板成本。
- 三路 ADC 与两路 I²C、两路 SPI、一路 DC **都动不了**（§3.1–§3.4）。
  因此**只有 5 个功能是可搬动的**：`EC11_A`(GPIO2)、`EC11_B`(GPIO8)、`EC11_SW`(GPIO13)、
  `PA_PWR_PWM`(GPIO12)、`KEY_USER`(GPIO9，**不可搬**，见下)。
- `KEY_USER` 受 strapping 绑定：GPIO9 是 BOOT 键，**上电前不可下拉**。
  理论上可把「BOOT 键」保留在 GPIO9 而把"用户按键"功能另挂扩展器，
  但这既省不下 GPIO9（仍要接 BOOT），也没有意义 → **视为不可搬**。

### 5.1 方案 A —— 保持现状（12/12 用满）

| 维度 | 内容 |
|------|------|
| **收益** | ① 零改动、零验证成本；② EC11 直连，判向最可靠、手感最好（中断驱动，无 I²C 延迟）；③ ADC/I²C/SPI 全在真引脚，最干净；④ 固件已实测通过（附录 A） |
| **代价** | GPIO12/13 永远占用 MSPI 簿记保留脚；GPIO2/GPIO8 被 EC11 长期占住 strapping |
| **风险** | ① 🔴 **flash 模式一旦被改回 QIO，GPIO12/13 立即变回 SPIHD/SPIWP → 两个功能失效 + 板子起不来**（本板 flash 的 HD/WP 未接 ESP32）；② 🟠 「上电/复位瞬间转动旋钮」→ GPIO2/GPIO8 被判低 → 启动模式异常；③ 🟢 每次 `gpio_config()` 前必须记得 `gpio_reset_pin()` 先解除保留，否则日志出现 conflict 警告（**功能不受影响**，已实测） |
| **需要的代码改动** | **0 行** |

### 5.2 方案 B —— 只释放 `EC11_SW`（最小步）

**动作**：`EC11_SW` → TCA9535（P1.0），释放 GPIO13。

| 维度 | 内容 |
|------|------|
| **收益** | ① 若**同时**把 `PA_PWR_PWM` 挪来 GPIO13，就能把 GPIO12 还给 MSPI（"方案 B+"）；② 仅做 `EC11_SW` → TCA9535 这一步的话，收益只是**腾出一个脚给别的用途**（本板当前没有待补的引脚需求）；③ 扩展器占用 7 → 8/16，仍有 8 位余量 |
| **代价** | ① 按键响应由**中断驱动**降级为**轮询**（ADR-0008 §8.3 量化：最坏 20 ms 延迟）；② I²C 负载增加（50 Hz 轮询 ≈ 0.3% 总线占用）；③ 需要 `bsp_io_expander` 实现在先；④ 失去"按键可从深睡唤醒"的能力（**本工程当前不用深睡**，无实际损失） |
| **风险** | 🟢 低。按键是**人手时间尺度**（>100 ms），20 ms 轮询完全够用；且按键与编码器在同一颗芯片上，可**在编码器轮询里顺带读 SW**，不额外增加事务 |
| **代码改动量** | 中：`board_pins.h` 删 `BOARD_EC11_SW`、`bsp_board.h` 删枚举、`bsp_board.c` 删初始化与自检、`bsp_io_expander` 实现按键读取、`drv_ec11`/`drv_keys` 改写；ADR-0008 §8.3 需回退说明 |
| **注意** | **这一方案并没有解决 GPIO12/13 的风险**——`EC11_SW` 让出的 GPIO13 若不用就会被 `PA_PWR_PWM` 占回（"B+"），**总占用仍是 12/12**。若 GP3 空着不用，则是"11/12 用满、GPIO12 风险保留"。**无论哪种，GPIO12 的风险都不动。** |

### 5.3 方案 C —— 彻底避开 GPIO12/13（任务描述推演的完整版）

**三步动作**：

1. `EC11_SW` → TCA9535 **P1.0**（复用 ADR-0008 §8.2 的原始设计，即撤销 §8.3 的"改直连"）
2. `EC11_A/B` → TCA9535 **P1.2/P1.3** → 释放 **GPIO2 / GPIO8**
3. TCA9535 **`INT`** → **GPIO13**（复用第 1 步腾出的脚，不额外增加引脚需求）
4. `PA_PWR_PWM` → 仍留在 **GPIO12** ← 🔴 **因为没有非 strapping 的空脚可用**

**结果（现实版）**：`EC11` 与 `INT` 只是让 GPIO2/8/13 **换了用途**（13 从"按键输入"变成"中断输入"），
GPIO12 原封不动。**净余 2 个真引脚 = GPIO2、GPIO8，且二者是 strapping 脚。**

> ⚠️ **必须先算清"INT 引脚从哪来"这笔账**（任务描述中未点明）：
> ADR-0008 §6 已经给出答案 —— **`EC11_SW` 空出的 GPIO13 正好用来接 `INT`**。
> 所以 INT **不是**第 13 个需求，而是**回收再利用**。真实账本：
>
> | 项 | 引脚 |
> |----|------|
> | 腾出 | GPIO2、GPIO8、GPIO13（三个） |
> | 搬走 | `EC11_SW` → TCA P1.0；`EC11_A/B` → TCA P1.2/P1.3 |
> | 回收 | `INT` → **GPIO13**（复用腾出的脚，不额外增加需求） |
> | **净余** | **2 个真引脚（GPIO2、GPIO8）** |
>
> **但这个账本有一个致命前提**：GPIO2/GPIO8 是 **strapping 脚**，
> 净余的两个引脚**不能随便用**（见下方风险③与 §5.5 约束 6），
> 而 `PA_PWR_PWM` 恰好是"上电必须为 0"的信号 → **它搬不过去**。
> 于是第三步「`PA_PWR_PWM` → GPIO2/GPIO8」**在当前设计下不成立**（见下方风险③），
> 方案 C 因此**无法完整达成"GPIO12/13 双双空置"** ——
> 除非改用 §6.2 的方案 C′（把 PWM 搬到 strapping 脚，需硬件反相配合）。
> TCA9535 占用：7 → 10/16（P1.0/A/B 共 3 位；`INT` 是独立引脚、不占位）→ 余 6 位。

| 维度 | 内容 |
|------|------|
| **收益** | ① 🔴 **彻底消除"改回 QIO 就变砖"的残留风险**（这是最强动机）；② 🟠 **消除 EC11 在 strapping 脚上的人手扰动风险**；③ **净余 2 个真引脚**（GPIO2、GPIO8）——但二者仍是 strapping 脚，**只能承载"上电为高"的信号**；④ ADC/PWM 原则依然满足（LEDC 任意脚） |
| **代价** | ① **编码器判向从"两个原子读电平"退化为"两字节 I²C 寄存器读"**——需要软件去抖与状态机；② 中断只能投递到任务（**ISR 里不能做 I²C 读**，会加锁/阻塞），响应链路变成 `INT → ISR → 队列 → 任务 → I²C 读 → 解码`；③ 增加 I²C 事务（每次旋转 1–2 次读）；④ 调试复杂度上升（编码器问题不再能用万用表/逻辑分析仪直接看 A/B） |
| **风险 ①（丢步）** | **量化核算**：机械编码器手转最快 → ① 20 格/圈、10 圈/s = 200 格/s = **5 ms/格**（一格 = 一个完整正交周期，含 4 个边沿）；② 30 格/圈、5 圈/s = 150 格/s = 6.7 ms/格。TCA9535 @400 kHz 读 2 字节（含地址与 ACK）= (1 + 2 + 1 + 2) 字节 ≈ 6 × 9 bit = 54 bit ≈ **135 µs**，加驱动栈开销按 **200 µs** 计 → **余量约 25 倍**。若改用**一次事务读两个端口寄存器**（写指针 0x00 → repeated START → 读 2 字节），仍是 2 字节。**结论：余量充足，但前提是 ① A/B 必须在同一事务内读取或做去抖状态机，② 禁止在旋转期间插入长 I²C 突发（ATU 调谐）** |
| **风险 ②（I²C 争用）** | 见 §5.6 专项 |
| **风险 ③（strapping，本审计新增）** | 把 `PA_PWR_PWM` 放到 GPIO2/GPIO8 **并没有消除 strapping 风险，只是换了个形式**：EC11 是"人转才拉低"（偶发），而 PWM 是**上电即持续输出**（常态）。且 `bsp_board.c` 上电即 `gpio_set_level(PA_PWR_PWM, 0)`（低压 = 低功率档）→ **0 V 直接判为低 → 启动异常**。🔴 **这是任务描述推演 3 的隐患：在"低电平 = 低功率"的既有语义下，`PA_PWR_PWM` 绝对不能落在 strapping 脚上。** |
| **需要的代码改动量** | **大**：`bsp_io_expander`（先实现）、`drv_ec11` 重写（I²C 读 + 状态机 + 去抖）、`bsp_board` 增加 INT 引脚与 ISR 投递、`rf_power`/`drv_pa` 换引脚、`board_pins.h`+`bsp_board.h`+公开仓 4 份文档同步 |

### 5.4.1 备选 A′ —— 放弃 `ADC_VBAT` 换 GPIO3（任务描述提到的"更简单方案"）

**动作**：删掉电池分压，GPIO3 改接 `PA_PWR_PWM`，释放 GPIO12/13。

| 维度 | 评估 |
|------|------|
| 收益 | 改动比方案 C 小得多（不动 EC11）；一次解决 GPIO12 |
| 代价 | 🔴 **失去电池电压监测** —— 而 [docs/05 §5.2](05-hw-sw-interface-contract.md) 的**遥测字段契约里"电池电压 uint16 mV"属于"必须全部实现"**；[README §3.3](../README.md) 的竞赛模式（**2024 基线 7 种，模式层/协议层已全部实现**）也都依赖电量管理。删掉它需要先改契约 |
| 另一代价 | **这条 ADC 通道不会再有第二次机会**——`GPIO3` 一旦改成数字输出，ADC1 只剩 GPIO2（被 `EC11_A` 占）与 GPIO4（被 `I²C_SDA` 占），**模拟输入余量归零** |
| 结论 | ❌ **不推荐**。用"失去核心遥测量"换"少一个残留风险"不合算；且 GPIO13 仍被 `EC11_SW` 占用、GPIO12 只是换了个占用者，**"避开 12/13"只完成一半** |

### 5.4.2 备选 B′ —— LCD 用 9-bit SPI 去掉 `LCD_DC`（任务描述问到的方案）

**已核实为不可行**，两条独立理由：

1. **控制器不支持**：ST7567 是"8 位数据 + `A0`（命令/数据选择）"接口。串行模式下 `A0` 是
   **与数据字节并行的独立选通信号**，在 `/WR`（SCLK）边沿与数据一起被采样 →
   **不存在"第 9 位即 A0"的帧格式**。
2. **ESP32-C3 的 SPI2 不提供这个能力**：数据手册 §4.2.1.2 明确 "Data transmission is in **bytes**"，
   且特性表未列任何 LCD/DC（A0）信号。ESP-IDF 的 `spi_master` API 以字节为单位，
   走 DMA 连非 8 的倍数都困难。（注：ESP32-S2/S3 另有专用 LCD 外设，**C3 没有**。）

**结论**：`LCD_DC` 必须占用真引脚。→ 无论选哪个方案，**GPIO6/7/10 都不可动**。

### 5.4.3 备选 D′ —— UART0 走 GPIO Matrix 重映射到 GPIO2/8（结论：无用）

GPIO20/21 虽标为 UART0，但 UART0 可经 GPIO Matrix 映射到任意脚。然而：

- 上电早期的 **ROM 引导日志与 `boot:` 行**固定走 GPIO20/21 的 UART0 pads；
- 本板**已经改用原生 USB-Serial/JTAG 作为主控制台**（附录 A 可见 `GPIO 20 and 21 ...` 警告已消失）；
- 而 GPIO20/21 本来就不在 12 个可用引脚里（它们不是"被浪费的引脚"）。

**结论**：重映射 UART0 **一个引脚也省不下来**，只会把早期启动日志搞丢。❌ 否决。

### 5.4.4 备选 D —— `LCD_DC` 挂 TCA9535（ADR-0008 §6 的回退方案 2）

| 维度 | 评估 |
|------|------|
| 定量核算 | 128×64 单色 = 1024 字节帧缓冲。刷新一屏需 **1024 次 DC 翻转**；每次 DC 变化至少要一次 I²C 写（TCA9535 输出寄存器，单字节写 ≈ 1 地址 + 1 数据 ≈ 18 bit ≈ **45 µs**）→ **一屏最少 46 ms 纯 DC 开销**，且必须与 SPI 严格交替 ⇒ 软件时序极度脆弱、显示刷新率被锁死在 ~10 fps 以下 |
| 另一面 | 即使采用"批量同类型字节"优化（把一帧拆成 k 段命令/数据交替），段数 k≈几十，可把开销压到几 ms；但**这要求 framebuffer 在 RAM 里按段重组**，显示驱动复杂度显著上升 |
| 收益 | 空出 GPIO10 |
| 结论 | ⚠️ **理论可行但工程上不划算**。ADR-0008 已把它列为"可选回退方案"并注明"让显示依赖 I²C 子系统"。**若走方案 C 且上述账本已给出 1–2 个空闲引脚，则完全没必要动 LCD_DC** |

### 5.5 🔴 方案 C 的关键约束（本审计新增，任务描述中未提及）

**约束 0 —— 本节的 6 条约束是"若用户决定走方案 C"时的设计前置条件，不影响 §6.4 的推荐。**

**约束 1 —— INT 需要一根真引脚，但它可以由空出的 GPIO13 承担。**
`EC11_SW` 搬走后 GPIO13 正好空出来接 `INT`，所以 **INT 不是新增需求**（§5.3 已算账）。
代价是 GPIO13 **仍在被使用**，只是用途从"输入按键"变成"输入中断"——
**它仍然是 MSPI 簿记保留脚**，因此"彻底避开 GPIO12/13"的目标**只完成了一半**。

**约束 2 —— INT 是"任一输入变化"的或信号。**
TCA9535 的 INT 在**输入端口数据变化**时置位（输出端口变化不触发）。当前设计里
P0.0–P0.5（继电器）与 P1.1（背光）都是**输出**，因此若把 EC11 的 A/B/SW 全放输入，
**所有 INT 中断都源自编码器**，没有额外噪声源 —— 这一点对方案 C 有利 ✅。

**约束 3 —— INT 是开漏输出，需要外部上拉。**
TCA9535 的 I/O 有内部 100 kΩ 上拉，但 `INT` 引脚**没有**。必须在板上加 **10 kΩ 上拉到 3.3 V**
（与 I²C 上拉同一网络即可）。**PCB 未打样 → 现在加成本为 0**。

**约束 4 —— 编码器输入可依赖 TCA9535 的内部上拉，但外部上拉更稳。**
TCA9535 的 I/O 内部有 100 kΩ 上拉，EC11 静止时可以被拉高；但 100 kΩ 在射频功放附近的
EMI 环境下偏弱，建议**保留外部 10 kΩ**（成本极低）。这与当前"A/B 各加 10 kΩ"的要求一致。

**约束 5 —— A/B 必须放同一端口的相邻位（P1.2/P1.3），且最好用一次事务读回。**
理由：正交解码读两次寄存器之间存在时序窗口。虽然 TCA9535 的输入端口**不是**采样锁存型
（读回的是当前引脚状态），但**同一端口的两个位在同一次读里天然一致** ——
把 A、B 放在 P1.2/P1.3（同端口）即可保证方向判定的一致性。**不要把 A/B 分到 P0/P1**。

**约束 6 —— GPIO2/GPIO8 即使腾出来，也仍是 strapping 脚。**
腾出后**不能随便挂"上电为低"的东西**。具体到 `PA_PWR_PWM`：

| 落点 | 上电电平 | 是否安全 | 说明 |
|------|---------|---------|------|
| GPIO2 或 GPIO8 | 软起后由 `bsp_board.c` 置 **0**（低压 = 低功率） | 🔴 **不安全** | strapping 阈值 ≈ 0.75×VDD = 2.48 V，0 V 判为低 → 启动模式异常 |
| GPIO2 或 GPIO8（硬件把 FB 极性反相，**PWM 高 = 低功率**） | **高** | ✅ **可行**（上电即进入最低功率档） | 需要硬件改 FB 分压极性 + 固件反向占空比。**上电到引脚被驱动的这段窗口内，功放可能以最低档短暂工作**——与 §2.5「上电不给功放功率」的既有约定不同，需硬件确认升压模块的软起行为 |
| GPIO3（放弃 ADC_VBAT） | 0 | ✅ | 但代价见 §5.4.1 |
| GPIO10（LCD_DC 让位） | 0 | ✅ | 代价见 §5.4.4 |

> 🔴 **结论修正**：任务描述推演 3「`PA_PWR_PWM` → GPIO2 或 GPIO8」**不能照现状语义直接采用**
> （现状是"低 = 低功率"，上电置 0 会判低）。若坚持方案 C，两条出路：
> **(a)** 硬件反相 FB 极性（→ §6.2 的 C′，可行）；**(b)** 干脆不用 INT，把 PWM 放到**干净的 GPIO13**
> （→ §6.2.1 的 C.1，最推荐）。
> 若两条都不做，则 `PA_PWR_PWM` 只能留在 GPIO12 —— **方案 C 不成立**
> （"以为避开了 12/13，其实 GPIO12 还在用"）。

### 5.6 专项：CW 键控（I²C）与编码器任务的优先级设计

**问题**：CW 键控通过 I²C 写 Si5351（`CLKx_DIS`）实现，与 TCA9535 共享同一条总线。
若编码器也走 I²C，两者会争用总线。

| 项 | 数据 |
|----|------|
| 键控事务 | 单次 ≈ **60 µs**（[docs/05 §2.5](05-hw-sw-interface-contract.md) 实测值） |
| 12 WPM 点长 | 12 WPM → 1 单位 = 1200/12 = **100 ms**；点 = 1 单位 = 100 ms，划 = 3 单位 = 300 ms |
| 键控占比 | 60 µs / 100 ms = **0.06%** |
| 编码器一次读 | ≈ **135–200 µs**（2 字节 @400 kHz + 驱动开销） |
| 编码器最坏请求率 | 5 ms/格 → 200 次/s → 200 × 200 µs = **4% 总线占用**（仅在疯狂旋转时） |

**设计结论（可直接落地）**：

1. **键控任务优先级必须高于编码器任务**，且两者共用 `bsp_board_i2c_lock()` 互斥量
   （FreeRTOS 互斥量自带优先级继承，可避免优先级反转）。
2. **最坏情况的最坏延迟**：编码器持锁 200 µs → 键控最多等 200 µs → 相对 100 ms 点长
   是 **0.2%**，**无感知、不丢点**。✅
3. **不需要为编码器做"发报期间暂停轮询"**（这是好消息：任务描述担心的"发报期间不能转旋钮"
   其实不成立，因为 200 µs 的等待对键控完全安全）。
4. **唯一必须禁止的**：发报期间做 **ATU 调谐**（连续几十毫秒的 I²C 突发）。这与当前
   [docs/05 §2.5](05-hw-sw-interface-contract.md) 已有的约束"ATU 调谐须在非发射态"一致，**无新增约束**。
5. **INT 的价值**：空闲时**完全不占 I²C**（对比 50 Hz 轮询的 0.3%）。旋转时才产生事务 →
   这是方案 C 相对"纯轮询"的关键技术优势。

## 6. 推荐方案与理由

**建议由用户拍板**，但审计给出如下倾向性意见（附理由，不含替代判断）：

### 6.1 短期（本次不改分配）：**方案 A + 强化纪律**

理由：
1. 「ADC/PWM 用真引脚」这条**核心原则已经满足**，没有必须改的硬伤（§3）。
2. 方案 C 在当前引脚预算下**无法完整成立**（§5.5 约束 6）：`PA_PWR_PWM` 找不到一个
   既非 strapping、又已腾出的落点。要让它成立，必须额外接受 §5.4.1（失去电池监测）
   或 §5.4.4（显示依赖 I²C）的代价。
3. 方案 B 单独采用**收益/代价比最差**：只把 GPIO13 让出去，GPIO12 的风险原封不动。

**纪律补充（比改分配更划算）**：

| 措施 | 强度 |
|------|------|
| ① 在 `sdkconfig.defaults` 里加**注释警告块**说明"改 QIO = 板子起不来" | 🟠 |
| ② 在 CI 或构建脚本里加**断言**：`CONFIG_ESPTOOLPY_FLASHMODE_DIO` 必须为 y，否则构建失败 | 🔴 **最强** |
| ③ `board_pins.h` 的 `BOARD_FLASH_MODE_DIO` 宏目前只是注释性的常量，可加 `_Static_assert` 关联 sdkconfig | 🟠 |
| ④ 原理图上把 GPIO12/13 明确标注"⚠️ 仅 DIO 可用" | 🟠 |

### 6.2 变体 C′ —— 保留 INT、把 PWM 放到 strapping 脚（需硬件配合）

```
EC11 A/B/SW  → TCA9535 P1.2 / P1.3 / P1.0      （三根线，全输入，A/B 同端口 P1）
TCA9535 INT  → GPIO13                          ✅ 复用腾出的脚
PA_PWR_PWM   → GPIO2 或 GPIO8                  ⚠️ 见下方两个必须接受的前提
GPIO12       → 空置                            ✅ 彻底交还 MSPI
```

**两个必须接受的前提**（否则组合不成立）：

| # | 前提 | 说明 |
|---|------|------|
| P1 | 🔴 **`PA_PWR_PWM` 的极性必须与 strapping 要求一致**：上电为**高** = 低功率档 | 现在的语义是"低 = 低功率"（`bsp_board.c` 上电置 0），直接搬到 GPIO2/8 会 **0 V 判低 → 启动异常**。必须由**硬件把升压模块 FB 的分压极性反相**，或改用在 strapping 脚上"上电自然为高"的其它调压方式 |
| P2 | ⚠️ **接受上电瞬间的功放功率不确定性** | 反相后，strapping 上拉会让 PWM 在上电时**为高**。若"高 = 低功率"，则上电瞬间是**最低功率**——**这一次反而比现状更安全** ✅。但如果保留"高 = 高功率"的直觉语义，就会在上电瞬间给出满功率（与 §2.5「上电不给功放功率」的约定冲突）。**因此 P1 与 P2 必须一起设计并实测。** |

- **收益**：GPIO12 **空置**；GPIO13 只作 `INT` 输入（不写电平、不驱动）；**"GPIO12/13 双双不再作为功能引脚"达成**；EC11 撤出 strapping 脚的人手扰动风险。
- **代价**：`PA_PWR_PWM` 落到 strapping 脚，**引入了一组新的、需要硬件配合的约束**（P1/P2）；
  编码器判向依赖 I²C（见 §5.3 风险①）；需要实现 `bsp_io_expander` 与 INT 投递链路。
- **审计意见**：C′ 把风险从"GPIO12/13 与 flash 模式耦合"**换成了**"PWM 与 strapping 耦合"。
  两者都是"配置错了就起不来"，但**后者可以用原理图上的固定电阻网络解决，而前者只能靠纪律**。
  不过 C′ 有一个明显更好的兄弟方案 —— **§6.2.1 的 C.1**：既然可以不用 INT，
  把 PWM 放到**干净的 GPIO13** 就行，**完全不必碰 strapping 脚**。

#### 6.2.1 变体 C.1 —— **不用 INT 引脚**（本审计认为性价比最高的一条）

如果放弃"中断触发"、接受**轮询**，则 GPIO13 就不必用作 INT，可以改作 `PA_PWR_PWM` 的落点：

```
EC11 A/B/SW  → TCA9535 P1.2 / P1.3 / P1.0      （全输入；不用 INT，无 INT 引脚）
PA_PWR_PWM   → GPIO13                          ✅ 干净脚：LEDC 可映射，上电置 0 不涉及 strapping
GPIO12       → 空置                            ✅ 彻底交还 MSPI
GPIO2 / 8    → 空置                            ✅ 仅需外部 10 kΩ 上拉满足 strapping
```

- **收益**：**不需要任何 INT 引脚**，也**不碰 strapping 脚** → 是"GPIO12 空置"这一目标下
  **最简单、风险最低**的组合；`EC11` 撤出 GPIO2/GPIO8 后，strapping 只剩"两个空脚 + BOOT"。
- **代价**：编码器与按键必须**轮询**。按 §5.3 的量化，要在 5 ms/格下不丢步，
  采样周期需 ≤1 ms → **1 kHz 轮询 = 2000 次 I²C 事务/s ≈ 4% 总线占用**，
  且与 CW 键控争用（虽然 §5.6 已证明 200 µs 级等待对键控安全）。
- **折中**：**动态轮询率** —— 平时 50 Hz（0.3% 占用）；一旦检测到任一位变化，
  在接下来 100 ms 内提升到 1 kHz。这样怠速开销低、旋转时不丢步。
- **审计意见**：⚠️ 固件复杂度不低（动态轮询 + 去抖状态机），但**硬件侧零约束、零风险**，
  且**不需要任何额外上拉/反相电路**。**在"想动 GPIO12"的前提下，这是本审计推荐的首选路径。**
- 🔴 **本变体独有的风险（必须列入）**：**I²C 失效 = 旋钮完全失效**。
  当前设计里编码器是独立引脚，I²C 挂了仍能转旋钮（至少能看/操作备用路径）；
  改成 C.1 后，人机输入 100% 依赖 `bsp_io_expander` 与那颗 TCA9535。
  缓解：① 启动自检必须包含"TCA9535 读回 + EC11 静止电平"；② 同时保留 GPIO9（BOOT 键）
  作为**不依赖 I²C 的兜底输入**；③ 掉总线检测 → 液晶提示 + 看门狗复位。

### 6.3 另一条彻底方案 —— 动 `LCD_DC`（代价更高，不推荐）

```
EC11 A/B/SW  → TCA9535 P1.2 / P1.3 / P1.0
TCA9535 INT  → GPIO13
PA_PWR_PWM   → GPIO10（LCD_DC 让位）→ LCD_DC 挂 TCA9535
```

- **收益**：GPIO12/13 **双双空置**，MSPI 风险彻底消除；`LCD_DC` 的 I²C 化代价见 §5.4.4。
- **代价**：显示刷新依赖 I²C 子系统（ADR-0008 §5 已把这条列为"可选回退方案"并注明其代价）；
  且**引入了更糟的失败模式**——显示是主状态指示，而 I²C 上还有键控与继电器。
- **审计意见**：**用"显示依赖 I²C"换"消除 QIO 风险"是等价交换，不是净改善。**

### 6.4 一句话推荐

> **首选：方案 A（保持现状）+ 加构建期 DIO 断言** —— 原则已满足，风险用**纪律**守住，零成本。
>
> **若用户认为 QIO 残留风险不可接受**，按"推荐度"排序：
> 1. **C.1（§6.2.1）**：`EC11` 全部挂扩展器、**不用 INT**、`PA_PWR_PWM` 挪到 **GPIO13**
>    → **GPIO12 空置**；硬件零新增约束、不碰 strapping；代价是编码器改**动态轮询**（固件复杂度）。
>    ⭐ **本审计推荐此路径。**
> 2. **C′（§6.2）**：`EC11` 全部挂扩展器 + `INT` 接 **GPIO13**、`PA_PWR_PWM` 挪到 **GPIO2/GPIO8**
>    → **GPIO12 空置**；代价是 PWM 落到 strapping 脚，**必须硬件配合反相 FB 极性**（P1/P2）。
> 3. **§6.3 动 `LCD_DC`**：唯一能让"GPIO12 与 GPIO13 都不接功能"的方案，
>    代价是**显示依赖 I²C**（ADR-0008 自己把它标为"可选回退方案"）。**不推荐。**
>
> ❌ **不推荐**：方案 B 单独采用（收益最薄）；备选 A′（用"失去电池监测"换风险，且破坏遥测契约）。
>
> ⚠️ **必须澄清的一点**：严格照任务描述的三步走**不成立**（`PA_PWR_PWM` 搬不过去，
> 因为 GPIO2/GPIO8 是 strapping 脚而 PWM 上电必须为低）。若不修正这一步，
> 会得到一个"以为避开了 12/13、其实 GPIO12 还在用"的假结论。

## 7. 残留风险与约束

| # | 风险/约束 | 等级 | 触发条件 | 缓解 |
|---|----------|------|---------|------|
| R1 | 🔴 **flash 模式改回 QIO 则 GPIO12/13 方案失效且板子无法启动** | **高** | 任何人删除/覆盖 `CONFIG_ESPTOOLPY_FLASHMODE_DIO=y` | 构建期断言（§6.1 措施②）；原理图标注；本文件 + ADR-0008 + [docs/05 §2.6.2](05-hw-sw-interface-contract.md) 三处互相引用 |
| R2 | 🟠 strapping：上电/复位瞬间转动旋钮 → GPIO2/GPIO8 判低 | 中 | 人手动作与上电瞬间重合（概率低） | EC11 A/B 各 10 kΩ 上拉；启动画面提示；看门狗复位重试 |
| R3 | 🟠 每次 `gpio_config()` 前必须 `gpio_reset_pin()` 解除 MSPI 簿记 | 中 | 新驱动忘了做，日志出现 `conflict found for GPIO[12/13]` | **功能不受影响**（只警告），但会污染日志；建议在 `bsp_board` 提供统一入口 |
| R4 | 🟡 MSPI 簿记解除后，深睡隔离逻辑会处理 GPIO12/13 | 低 | 未来启用深睡 | 当前不用深睡；若启用须复核 `sleep_gpio.c` 行为（`bsp_board.c` L241–245 已记录） |
| R5 | 🟡 若实施 C / C′ / C.1 / B：编码器判向依赖 I²C 时序 | 中 | 快速旋转 + 总线繁忙 | 同事务读同端口；去抖状态机；键控优先级最高 |
| R6 | 🟡 若实施 C′：`TCA9535 INT` 开漏需外部上拉 | 低 | 漏画上拉 → INT 悬空、误中断或完全无中断 | 原理图加 10 kΩ 到 3.3 V（C.1 不用 INT，无此风险） |
| R7 | 🟡 P1.0 在 ADR-0008 §8.2 与 §8.3 之间反复（按键挂扩展器 → 直连 GPIO13 → 若走 C/C′/C.1 又回扩展器） | 低 | 反复变更导致固件与文档漂移 | 改分配时必须**一次改齐**：公开仓 5 处 + 私有仓 3 处（见 §8 清单） |
| R8 | 🔴 若实施 C′：`PA_PWR_PWM` 落 strapping 脚而**未反相 FB 极性** → 上电置 0 导致启动异常 | **高（若误用）** | 见 §5.5 约束 6 | 🔴 要么**硬件反相极性**（PWM 高 = 低功率，见 §6.2 P1），要么**改用 C.1**（PWM → GPIO13，无此问题） |
| R9 | 🟠 若实施 C.1：**I²C 失效 = 旋钮完全失效**（人机输入 100% 依赖扩展器） | 中 | TCA9535 掉线 / 总线锁死 | 启动自检读回；保留 GPIO9(BOOT) 作不依赖 I²C 的兜底输入；掉总线提示 + 看门狗复位 |

#### 12.5.1 决策理由：**没有 ADC 通道可分配给 NTC**

`drv_analog` 可用的 **12 个 GPIO（GPIO0–8、10、12、13）已全部用满**，
其中 ADC1 的 5 个通道（CH0–CH4）**无一空闲**——这正是 §3.1 与 §2 核对表的结论：

| ADC1 通道 | 引脚 | 归属 | 能否让给 NTC |
|---|---|---|---|
| CH0 | GPIO0 | `ADC_FWD` SWR 前向检波 | ❌ 不可（SWR 判决必需） |
| CH1 | GPIO1 | `ADC_REV` SWR 反射检波 | ❌ 不可（SWR 判决必需） |
| CH2 | GPIO2 | `EC11_A` 编码器 A 相 | ❌ 已被占用（且是 strapping 脚） |
| CH3 | GPIO3 | `ADC_VBAT` 电池电压 | ❌ 不可（电池监测必需） |
| CH4 | GPIO4 | `I2C_SDA` I²C 数据线 | ❌ 已被占用 |

- 空闲的 ADC1 通道只剩 GPIO2（CH2）与 GPIO4（CH4），**两者都已被 EC11_A / I²C_SDA 占用**
  （§3.1 原文：*"空闲的 ADC1 通道只剩 GPIO2（CH2）与 GPIO4（CH4），两者都已被 EC11_A / I²C_SDA 占用"*）。
- 也就是说：**"用 MCU 读 NTC 做温度补偿 / 过温保护"这条路径在本板上物理不可实现**。
  要给它腾一个通道，就必须牺牲 SWR 前向/反射检波、电池监测、编码器或 I²C 中的一项，
  代价远高于收益（NTC 只提供"辅助性的热保护"）。
- 既然固件读不到温度，**保留 PA 模块上的 NTC 就只剩成本与失效点**（BOM 料、装配工序、
  一个可能虚焊的模拟节点），于是硬件侧同步删除。

> 12/12 用满 ⇒ 没有空闲 ADC 通道 ⇒ 温度功能无法落地 ⇒ 整体取消。

#### 12.6.1 触发原因：两条**误导性**簿记警告（实测）

改前启动日志：

```
W (198) gpio: conflict found for GPIO[10]                        ← LCD_DC
W (224) ledc: GPIO 12 is not usable, maybe conflict with others   ← PA_PWR_PWM
```

根因链（已在 ESP-IDF v6.1 源码逐层核实）：

1. `components/esp_driver_gpio/src/gpio.c` 的 `gpio_config()` 在**输出模式**下调用
   `esp_gpio_reserve(bit_mask)`，把该脚**重新登记为「已保留」**；若已被登记则打印
   conflict 警告，源码注释原文 *"Right now, we just give a warning."* —— **不 return、
   不 continue，照样完整配置**。
2. 旧 `bsp_board.gpio_init_board()` 对 GPIO2/8/9/**10**/12/13 调用了 `gpio_config()`
   → 把 GPIO10/12 登记为保留。
3. 随后 `drv_lcd12864` 对 **GPIO10** 再 `gpio_config(输出)` → conflict；
   `drv_pa` 的 `ledc_channel_config()` → `ledc.c` `_ledc_set_pin()` 再
   `esp_gpio_reserve()` → `GPIO 12 is not usable`。
4. 这解释了为什么早先给 GPIO12/13 加 `gpio_reset_pin()`「**只解决了一半**」：
   GPIO13 只被配置过一次 → 无第二条警告；GPIO10/GPIO12 有第二次配置 → 仍冲突。

> ⚠️ 两条警告都**不影响功能**（conflict 后不返回；LEDC 之后照样 `gpio_matrix_output`），
> 但它们是**误导性噪音** —— 将来真出问题会被忽略。本次是"澄清所有权 + 消除噪音"。

#### 12.6.2 重构后的所有权分配

| 引脚 | 所有者 |
|---|---|
| GPIO0/1/3（ADC） | `drv_analog` |
| GPIO2/8（EC11_A/B）、GPIO13（EC11_SW） | `drv_ec11` |
| GPIO4/5（I²C） | **I²C 驱动**（`i2c_new_master_bus()` 自行 reserve 与配置；**总线对象**仍归 `bsp_board`） |
| GPIO6/7（SPI2）、GPIO10（LCD_DC） | `drv_lcd12864` |
| GPIO9（KEY_USER） | `drv_keys` |
| GPIO12（PA_PWR_PWM） | **`bsp_board`（仅上电安全）+ `drv_pa`（LEDC）** |

**留在 BSP 的三项**（逐条理由）：

| 项 | 为什么不能交出去 |
|---|---|
| 引脚映射表 | 本来就是单一事实来源；纯数据，不涉及配置 |
| **GPIO12 上电安全**（抢先置低 + 内部下拉） | 从芯片复位到 `pa_init()` 之间有**几百 ms**，该脚接升压 FB，必须**最早**被钉在低电平。BSP 是 init 链第一步，只有它有资格做"上电瞬间"的动作；这是**安全**而非"外设配置" |
| **I²C 总线的所有权**（`i2c_new_master_bus` + 互斥量） | Si5351 与 TCA9535 **共享**同一条总线，且两者的驱动都晚于 BSP；总线对象必须有唯一所有者与唯一互斥量。⚠️ 但 **SDA/SCL 的 IO 配置归 I²C 驱动**（`i2c_new_master_bus()` 内部已完成 reserve/开漏/上拉/matrix 连接），BSP 不再动 GPIO4/5 |

#### 12.6.3 GPIO13 的"只撤销、不配置"（本次的关键细节）

`gpio_config()` 的 conflict 判定对**纯输入模式**同样成立 —— 源码里两条判定互补：

```
(reserved && input_en) || (reserved && !input_en)   ==   reserved
```

即 **只要该脚被 MSPI 保留，无论配成输入还是输出都会打警告**。因此
`bsp_board` 必须保留一次 `gpio_reset_pin(GPIO13)`（GPIO13 = SPIWP，被
`esp_mspi_pin_reserve()` 登记），**但只撤销保留位，不设方向、不设上下拉** ——
GPIO13 的"输入 + 上拉"完全由 `drv_ec11` 负责。

#### 12.6.4 撒手窗口的安全性（逐脚）

| 脚 | 撒手期间状态 | 判定 |
|---|---|---|
| GPIO2/8（EC11_A/B） | 外部 10 kΩ 上拉 → 高 | ✅ 且正是 strapping 要求的电平 |
| GPIO9（KEY_USER） | 外部上拉 → 高 | ✅ 未按下 |
| GPIO13（EC11_SW） | 外部 10 kΩ + 内部上拉 → 高 | ✅ 未按下 |
| GPIO10（LCD_DC） | 高阻 | ✅ SPI2 未建立、面板无时钟，不会产生误命令 |
| GPIO0/1/3（ADC） | 输入浮空 | ✅ 模拟脚，无害 |
| GPIO12（PA_PWR_PWM） | **BSP 已抢先置低**（输出 0 + 内部下拉） | ✅ 见 §12.6.2 与 docs/05 §2.10.2 |

#### 12.6.5 📌 连带的硬件建议（PCB 未打样）

**建议在 GPIO12 与升压 FB 之间加一颗 10 kΩ 下拉到 GND**（docs/05 §2.10.3）：
固件侧已覆盖"复位 → BSP 置低"之前的窗口之外的**全部**时间，硬件下拉则连那段
极短的高阻窗口也兜死。零风险、近乎零成本；采纳时需同步 `hardware/**` 的 BOM/原理图
与 docs/04。**本条是建议而非契约** —— 不采纳也不影响 §12.6 的成立。

#### 12.7.1 为什么是 0：`W0` 与 SEG 方向**耦合**

ST7567 是 **132 列**驱动、面板可见区 **128 列** ⇒ 可见窗口是 `SEG[W0 .. W0+127]`。
窗口是**从驱动器那一端**数起的，所以交换 SEG 方向（`0xA0` ↔ `0xA1`）等于从另一端开始填：

```text
W0' = (132 − 128) − W0 = 4 − W0
```

本机发的方向位是 `0xA0` + `0xC8` ⇒ 与之配对的是 **`W0 = 0`**（`0xA1` + `0xC0` 才配 `W0 = 4`）。
上游 u8g2 `csrc/u8x8_d_st7567.c` 的 `default_x_offset` / `flipmode_x_offset` 正是 4 与 0 这一对；
作者上一个**实测过**的项目 BBcall_APRS 在 180° 安装下的实板值也是 0。

#### 12.7.2 关键改动：把"方向位"与"列偏移"绑成**一个宏**

上一版把它们当**两个独立常量**，于是留下"**改一个忘另一个**"的窗口：两处一起改成 4
（模拟器自洽、看不出问题），而真板窗口是 0 ⇒ 画面整体错 4 列、一条边框整条丢失。
现在两者由**同一个宏**产生，结构上不可能只改一个：

```c
#ifndef LCD_MOUNT_180
#define LCD_MOUNT_180 1        /* 1 = 面板旋转 180 度安装（本机） */
#endif
#if LCD_MOUNT_180              /* (1) 方向位 */
#define ST7567_SEG_DIR_CMD  ST7567_CMD_ADC_NORMAL   /* 0xA0 */
#define ST7567_COM_DIR_CMD  ST7567_CMD_COM_REVERSE  /* 0xC8 */
#else
#define ST7567_SEG_DIR_CMD  ST7567_CMD_ADC_REVERSE  /* 0xA1 */
#define ST7567_COM_DIR_CMD  ST7567_CMD_COM_NORMAL   /* 0xC0 */
#endif
#ifndef LCD_COL_OFFSET        /* (2) 列偏移，随 (1) 取 0 / 4 */
#if LCD_MOUNT_180
#define LCD_COL_OFFSET 0u
#else
#define LCD_COL_OFFSET 4u
#endif
#endif
```

#### 12.7.3 复验（模拟器 + 交叉校验，无需硬件）

- `--selftest` **15/15 PASS**：`chip-diff = 0`（128 列原封不动落在 `[W0 .. W0+127]`）、
  `window-diff = 0`（可见窗口 == 帧缓冲 ⇒ 一格都不切）、`LCD_COL_OFFSET ==` 面板模型常量；
- `verify_bmp.py` 独立逐像素校验 **0 差异**（期望帧在 Python 里从零重算，偏移从固件头解析）；
- `--mount180` 画面 == 默认画面 rot180，**0 差异**（耦合公式 `W0 → 4 − W0` 的独立判据）；
- **A/B 对照**（`-DLCD_COL_OFFSET=4` 编一个"旧偏移"变体）：改后满高列 = `[0, 127]`（左右边框都在）、
  改前 = `[4]`（右边框整条丢失、左侧空 4 列），逐像素差 **606**（pattern）/ **1580**（charset）；
- **负对照**：对**改前**截图跑同一套校验**必须报差异** —— 否则校验器等于空转。

#### 12.7.4 与 §12.1 / §12.6 的关系

§12.1 决定"**引脚分配**保持方案 A 不变"、§12.6 决定"**固件内部所有权**如何划分"；
本决策只改**显示几何常量与文档**，**不占任何 GPIO**（ST7567 的 `CS`/`RST` 本就不占脚，见 docs/05 §2.2）。
⚠️ 若日后改安装方式或换模组，**方向位与 `W0` 必须同步重定**（换模组会换 SEG 走线）：
画 x=0 / x=127 两条 1 像素竖线，先定方向位，再读出 `W0`（见 docs/05 §2.2、§7 #10）。

## 13. 开发板选型对照：ESP32-C3 SuperMini vs 合宙 LuatOS ESP32C3-CORE

> **触发问题**（项目所有者，2026-09-27）：「ESP32-C3 SuperMini 的 GPIO 是不是不够？」
>
> 🔴 **本节不改变任何引脚分配。** §12.1 的「方案 A / 12 个可用脚用满 / DIO 强制断言」、
> §0 的一句话结论、`docs/05` §2.2 的引脚表**全部继续有效**，本节**没有**动固件仓任何文件。
> 本节只算「换板 / 不换板」这笔账，**结论不构成换板决定** —— 决定权在项目所有者。

### 13.1 结论先行

| 问题 | 答案 |
| --- | --- |
| SuperMini **缺几个脚**？ | **按"脚数"算：一个都不缺** —— 它引出 **13 个 GPIO**，我们正好需要 13 个；<br>**按"脚号"算：缺 2 个 —— `GPIO12` 与 `GPIO13`**，这两脚在 SuperMini 上**根本没有引出** |
| 精确到信号名 | `BOARD_PA_PWR_PWM`（原 GPIO12）与 `BOARD_EC11_SW`（原 GPIO13）**在原脚号上无处可放**；<br>唯一的落点是 **GPIO20 / GPIO21**（= UART0 的 RX/TX） |
| 隐藏冲突 | ⚠️ **SuperMini 的板载蓝色 LED 焊在 GPIO8 上（高电平有效）**，而 GPIO8 正是 `EC11_B` ——<br>与我们在本板上**拆掉 D5（GPIO13 的 LED）**、**D4（GPIO12 的 LED）**是**同一个问题**；<br>另外 GPIO2 / GPIO8 / GPIO9 三个 strapping **全部**被需求吃满（与现状相同） |
| 换过去的**收益** | ① 🔴 **R1（"改回 QIO 就变砖"）彻底消失** —— 这是**唯一实质电气收益**（SuperMini 不用 GPIO12/13，与 flash 模式解耦）<br>② 板子更小（22.52×18 mm）、更便宜、通常更好买 —— **采购/结构收益，不是引脚收益** |
| 换过去的**代价** | ① 两个信号必须**换号**（12→20、13→21）→ 文档 + 固件 pin map 按 `docs/05` §6 流程重走<br>② **必须处理 GPIO8 的板载 LED** ③ **放弃 UART0**（ROM 早期日志 + UART 下载）<br>④ 引脚余量 **+2 → 0** ⑤ 13 个信号与全部外设**重验** ⑥ 机械：仍需改 `mcu-ui-module` PCB（见 §13.6 (d)） |
| **引脚能力上的净收益** | **0**（换来换去还是"13 个信号用满、0 空闲"，只是把 DIO 耦合风险换成了 LED + UART0 两项新约束） |
| 推荐 | **留在 LuatOS ESP32C3-CORE**（§13.7）—— 不是"SuperMini 放不下"，而是**换板买不到引脚，却要付 4 项代价**；<br>只有当**采购/尺寸/供货**成为主要矛盾时才值得换，且必须先满足 §13.7 的三条前置条件 |

### 13.2 SuperMini 的精确 pinout（逐脚）

**来源**：① 厂家页（WMNologo / nologo.tech）规格与 Pin Usage 页；
② [ESPboards 的 SuperMini 引脚表](https://www.espboards.dev/esp32/esp32-c3-super-mini/)（自绘，注明依据 *ESP32-C3 Series Datasheet v2.4*）；
③ **strapping 三脚的权威依据**：乐鑫官方 [ESP32-C3-DevKitM-1 用户指南](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32c3/esp32-c3-devkitm-1/user_guide.html)（脚注 2 明确列出 GPIO2 / GPIO8 / GPIO9）。
⚠️ **不同厂家的 SuperMini 略有差异**，下表以"16 脚 2×8 排针"的通用版为准，**下单前必须对照实物丝印**。

| 排针# | 丝印 | GPIO | 板载占用 / 角色 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | `5V` | — | 电源 | — |
| 2 | `GND` | — | 地 | — |
| 3 | `3V3` | — | 电源 | — |
| 4 | `IO0` / `A0` | **0** | ADC1_CH0 | ✅ 干净（厂家列为首选脚） |
| 5 | `IO1` / `A1` | **1** | ADC1_CH1 | ✅ 干净 |
| 6 | `IO2` / `A2` | **2** | 🔴 **strapping**（**不选择启动模式**，启动模式由 GPIO9 决定；厂家建议外部上拉抗复位毛刺） | ⚠️ 与我们现状相同 |
| 7 | `IO3` / `A3` | **3** | ADC1_CH3 | ✅ 干净 |

| 9 | `IO5` / `A5` / `MISO` | **5** | ADC2_CH0 / SPI2（兼 `MTDI`） | ✅ 干净 |
| 10 | `IO6` / `MOSI` | **6** | SPI2 `CLK` 的 IO_MUX 默认脚（兼 `MTCK`） | ✅ 干净 |

**未引出（板上不可得）**：

| GPIO | 在 SuperMini 上为什么不可得 |
| --- | --- |
| **11** | `VDD_SPI`（flash 供电脚；只有烧 eFuse 才能当 GPIO，本工程已决定**不解锁**） |
| **12 / 13** | **flash 的 `SPIHD` / `SPIWP`**（`C:\esp\esp-idf\components\esp_hal_gpspi\esp32c3\include\soc\spi_pins.h:11-12`）——**本板根本没引到排针** |
| **14 / 15 / 16 / 17** | flash 的 `CS0` / `CLK` / `SPID` / `SPIQ` |
| **18 / 19** | **原生 USB**（`USB_D-` / `USB_D+`），走 Type-C 座，不引到排针 |

**三条待核实的说法 —— 结论**：

| 说法 | 核实结果 | 依据 |
| --- | --- | --- |
| 「GPIO8 = LED」 | ✅ **属实**，且**高电平有效**（厂家示例 `digitalWrite(led, HIGH)` 注释为 "turn the LED on"），另有红色电源灯不占 GPIO | nologo Pin Usage 页 + ESPboards |
| 「GPIO9 = BOOT」 | ✅ **属实**，且**同时是 strapping 脚**（低电平进下载模式） | ESPboards + 乐鑫 DevKitM-1 用户指南脚注 2 |
| 「GPIO2 = strapping」 | ✅ **属实**，但**它不决定启动模式**（决定者是 GPIO9）；厂家只建议外部上拉抗复位毛刺 | ESPboards + 乐鑫 DevKitM-1 用户指南脚注 2 + 本项目 §1.2 事实 3 |

> ⚠️ **ESPboards 电气注释勘误（本审计发现）**：该页把 `IO4–IO7` 注为 *"Bootstrapping pin; Flash data
> (FSPIHD/FSPIWP/FSPICLK/FSPID in internal-flash models)"* —— **两处都不准确**：
> ① 它们**不是 strapping 脚**（C3 的 strapping 只有 2/8/9）；② 它们是 **SPI2（通用 SPI）的 IO_MUX
> 四线脚**（`spi_pins.h:19-25`：`SPI2_IOMUX_PIN_NUM_HD=4 / WP=5 / CLK=6 / MOSI=7 / CS=10`），
> **与 flash 无关**（flash 在 SPI0/1 = GPIO12–17，`spi_pins.h:11-16`）。
> ⇒ 该页**只作"哪些脚被引出"的清单使用**，**电气注释一律不采信**。
> 这条勘误同时回答了一个安全问题：**I²C 放 GPIO4/5 在任何 C3 变体（含封装内 flash）上都安全**。

### 13.3 我们的 13 个信号 × 两板逐信号对照

**LuatOS 列的排针号**取自合宙官方文档的 32 脚表（来源 S-6，见 §13.8；完整映射见 §13.6(a)），
**这是"我们的 13 个信号是否真的都引出了"的直接证据**。

| # | 我们的信号 | 需要的电气特性（为什么不能随便挪） | SuperMini 可用脚 | SuperMini 判定 | LuatOS 排针#（现用） |
| --- | --- | --- | --- | --- | --- |
| 1 | `ADC_FWD` | **ADC1_CH0**（ADC2 未标定/部分版本不可用，WiFi 下更不可用） | GPIO0（pin 4） | ✅ | **2** |
| 2 | `ADC_REV` | **ADC1_CH1** | GPIO1（pin 5） | ✅ | **3** |
| 3 | `EC11_A` | 中断输入 + **strapping（上电须为高）** | GPIO2（pin 6） | ⚠️ 同现状 | **19** |
| 4 | `ADC_VBAT` | **ADC1_CH3** | GPIO3（pin 7） | ✅ | **20** |
| 5 | `I2C_SDA` | I²C0 SDA（matrix 可任意脚）+ 4.7 kΩ 上拉 | GPIO4（pin 8） | ✅ | **28** |
| 6 | `I2C_SCL` | I²C0 SCL | GPIO5（pin 9） | ✅ | **27** |
| 7 | `LCD_SCK` | SPI2 SCK（**恰好是 SPI2 IO_MUX 默认脚**，无 matrix 开销） | GPIO6（pin 10） | ✅ | **22** |
| 8 | `LCD_MOSI` | SPI2 MOSI（同上默认脚） | GPIO7（pin 11） | ✅ | **23** |
| 9 | `EC11_B` | 中断输入 + **strapping（上电须为高）** | GPIO8（pin 12） | 🔴 **板载蓝 LED 挂在此脚** | **29** |
| 10 | `KEY_USER` | 板载 BOOT 键（strapping，上电前不可下拉） | GPIO9（pin 13） | ✅ 正好复用 BOOT 键 | **30** |
| 11 | `LCD_DC` | 每字节翻转的**输出**，**必须直连**（9-bit SPI 已否决，§5.4.2）；恰好是 SPI2 `CS` 的 IO_MUX 默认脚 | GPIO10（pin 14） | ✅ | **21** |
| 12 | `PA_PWR_PWM` | **LEDC**（芯片 6 通道，可映射**任意** GPIO）+ **非 strapping**（上电即输出低电平） | ❌ 原脚 GPIO12 未引出 → 只能落 **GPIO20**（pin 16） | ⚠️ **须换号** | **4**（LED D4 已拆） |
| 13 | `EC11_SW` | GPIO 中断输入 + 10 kΩ 上拉（非 strapping） | ❌ 原脚 GPIO13 未引出 → 只能落 **GPIO21**（pin 15） | ⚠️ **须换号** | **10**（LED D5 已拆） |
| — | （USB 日志/下载） | 原生 USB-Serial/JTAG | GPIO18/19 走 Type-C | ✅ 等价 | 排针 **5 / 6** |
| — | （备用串口 UART0） | 本项目**已不用于控制台**（`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y`） | GPIO20/21 | ❌ **换板后会被占用** | 排针 **8 / 9** |

**三条电气结论**：
1. **ADC 全部满足**：三路模拟量（0/1/3）都在 **ADC1**，两板都直接可用（`adc_channel.h:9-22` 本机核对）。
2. **SPI 与 I²C 全部满足**：我们的 LCD 三脚（6/7/10）**正好是 C3 的 SPI2 IO_MUX 默认脚**（`spi_pins.h:19-25`），
   换到 SuperMini 后**完全不变**；I²C 走 GPIO matrix，4/5 可用。
3. **`PA_PWR_PWM` 可搬家**（LEDC 不绑脚），**`EC11_SW` 也可搬家**（任意 GPIO 都能中断）
   ⇒ 缺口是"**脚号**缺口"，不是"**功能**缺口"。

### 13.4 缺口清单（精确到信号名）

| # | 项 | 结论 |
| --- | --- | --- |
| G-1 | 🔴 **`BOARD_PA_PWR_PWM`（GPIO12）** | SuperMini **未引出 GPIO12**（flash `SPIHD`）⇒ **必须换号**（唯一落点 GPIO20） |
| G-2 | 🔴 **`BOARD_EC11_SW`（GPIO13）** | SuperMini **未引出 GPIO13**（flash `SPIWP`）⇒ **必须换号**（唯一落点 GPIO21） |
| G-3 | 🟠 **`EC11_B`（GPIO8）与板载蓝 LED 同脚** | 不是缺脚，是**负载冲突**：LED 会下拉高电平、缩小噪声容限；若引脚被驱高则 LED 点亮。**需与 D4/D5 同样处置**（拆除/不装/断开） |
| G-4 | 🟠 **UART0 被吃掉** | GPIO20/21 让给 PWM 与 SW ⇒ 失去"备用串口"（ROM 早期日志 + esptool UART 下载）。**主控制台已在原生 USB-Serial/JTAG**（实测 `VID:PID 303A:1001` / `CONFIG_ESP_CONSOLE_ROM_SERIAL_PORT_NUM=3`），故实际影响小 |
| G-5 | 🟡 **余量归零** | LuatOS 板引出 **15 个 GPIO**（官方"GPIO外部管脚15路"），本项目用 13、**留 2（GPIO20/21）作备用串口** = **余量 +2**；SuperMini 引出 **13**，需求 13 ⇒ **余量 0** |
| G-6 | 🟡 **strapping 占用不变** | 两板的 GPIO2/8/9 都被需求吃满（A/B 用 2/8，BOOT 键用 9）——**这是本设计固有的**，不是 SuperMini 引入的 |
| G-7 | ⚪ **不存在的缺口** | `GPIO11` 两板都用不上（需 eFuse，已决定不解锁）；`GPIO14–17` 两板都不可得（flash）。**这两条对选型没有区分度** |

**一句话**：**缺 2 根（GPIO12、GPIO13）→ 两个信号换号即可补上；但补上之后，SuperMini 的 13 个脚一个不剩。**

### 13.5 "省引脚"的五条思路 —— 逐条判定

| # | 思路 | 判定 | 依据 / 定量 |
| --- | --- | --- | --- |
| 1 | **EC11 的 A / B / SW 三线合并** | ❌ **不行** | 正交解码需要 A、B 两相**各自独立**（判向靠相位差）；SW 是独立开关，与 A/B 无电气关系。三者物理上就是 3 根线 |
| 2 | **去掉某路 ADC（如 VBAT）腾脚** | ❌ **功能裁剪，不推荐** | 会破坏 `docs/05` §5.2 遥测契约里的"电池电压 uint16 mV"（属**必须全部实现**），且 ADC1 通道用尽后**不会再有第二次机会**。详见 §5.4.1（备选 A′） |
| 3 | **LCD 用 9-bit SPI 去掉 `LCD_DC`** | ❌ **已否决** | ST7567 的 `A0` 是与数据并行的独立选通，**不存在"第 9 位即 A0"的帧格式**；C3 的 SPI2 数据手册明确 "Data transmission is in **bytes**"。详见 §5.4.2（备选 B′） |
| 4 | **编码器/按键挂 I²C 扩展器（TCA9535）** | ⚠️ **可行，但有代价** | 审计已量化：TCA9535 @400 kHz 读 2 字节 ≈ 135–200 µs，对"5 ms/格"的手转速度有 **~25 倍余量**；但 ① 判向退化为"I²C 读 + 去抖状态机" ② **I²C 挂了 = 旋钮完全失效**（需保留 GPIO9 BOOT 作兜底）③ 若走轮询，**必须与刚修好的 ADC 忙等修复共存**——采样循环里不得再插阻塞式 I²C 读。详见 §5.3 风险①、§6.2.1（C.1，本审计推荐的变体） |
| 5 | **已经省掉的脚（不可回收）** | ✅ 已用尽 | LCD `CS`→GND（省 1）· LCD `RST`→板复位（省 1）· CW 键控→Si5351 使能命令（省 1）。**这三处是本设计能只占 13 脚的原因**（见 §2.2、§2.5） |

### 13.6 四个方案对照 (a) (b) (c) (d)

#### (a) 留在合宙 LuatOS ESP32C3-CORE —— **现状，推荐**

| 维度 | 内容 |
| --- | --- |
| **引脚账** | 板子引出 **15 个 GPIO**（官方 32 脚表：IO0–IO10、IO12、IO13、GPIO20、GPIO21；另 18/19 = USB、PB_11 = GPIO11 需 eFuse）<br>本项目用 **13**（12 个可用脚 + GPIO9 BOOT 键），**GPIO20/21 留给 UART0 备用** ⇒ **余量 +2** |
| **13 个信号是否都引出** | ✅ **全部引出**：`IO0`→排针 2、`IO1`→3、`IO2`→19、`IO3`→20、`IO4`→28、`IO5`→27、`IO6`→22、`IO7`→23、`IO8`→29、`GPIO9(BOOT)`→30、`IO10`→21、`IO12`→4、`IO13`→10（合宙官方文档一手来源，见 §13.8） |
| **收益** | ① **零改动、零重验**（真机日志已实测，§9 附录 A）② EC11 **直连判向**最可靠 ③ 余量 +2 ④ ADC/I²C/SPI 全在真引脚 |
| **代价 / 风险** | ① 🔴 R1：GPIO12/13 与 flash 模式耦合（"改回 QIO 就变砖"）——**但已有构建期 DIO 断言 + 双向实测**（§12.1/§12.2），残留风险 = "有人既删断言又改 QIO" ② 🟠 R2：EC11 在 strapping 脚（靠人手纪律 + 10 kΩ 上拉）③ 必须拆板载 LED D4/D5（**已决策并落实**，§12 前置） |
| **一句话** | **原则已满足，风险用纪律与断言守住，成本 0** —— §6.1/§6.4 的推荐不变 |

#### (b) 换 ESP32-C3 SuperMini

| 维度 | 内容 |
| --- | --- |
| **引脚账** | 引出 **13 个 GPIO**（0–10、20、21）；需求 13 ⇒ **一个不剩**；`PA_PWR_PWM`→GPIO20、`EC11_SW`→GPIO21 |
| **收益** | ① 🔴 **R1 彻底消失**（不用 GPIO12/13，与 flash 模式解耦）② 22.52×18 mm / 更便宜 / 更好买 ③ 原生 USB 与现板等价（刷写与日志链路不变） |
| **代价** | ① 两个信号**换号** ⇒ 公开仓 5 处 + 私有仓 3 处同步（§8 清单）+ 按 `docs/05` §6 流程重走 ② **GPIO8 的 LED 必须处置**（G-3）③ **放弃 UART0**（G-4）④ **余量 0**（G-5）⑤ 13 信号 + LCD/EC11/ADC/I2C **全量重验** ⑥ 陶瓷天线的 WiFi/ESP-NOW 距离（§13.8 外部资料，公认弱项）需实测 ⑦ 机械：见 (d) |
| **判定** | ⚠️ **技术上可行（不缺功能），但净收益为负**：用"已缓解的 R1"换"4 项新代价 + 重验" |

#### (c) 换"引脚更多"的板 / 芯片

| 候选 | 引脚账 | 代价 | 判定 |
| --- | --- | --- | --- |
| **ESP32-C3-DevKitM-1**（官方，ESP32-C3-MINI-1） | 官方 J1+J3 引出 **15 个 GPIO**：IO0–10、**IO18、IO19、IO20、IO21** —— **同样没有 GPIO12/13**（MINI-1 的 4 MB flash 在封装内）。而且 **GPIO8 挂 RGB LED**、GPIO18/19 是 USB `D-`/`D+` | 与 SuperMini **同一笔账**（12/13 缺失 + GPIO8 有灯），只是多引出 18/19 —— 而占用 18/19 就等于**放弃原生 USB** | ❌ 对我们的需求**没有净优势** |
| **ESP32-S3**（GPIO 30+） | 引脚**绰绰有余**（我们只要 13），余量与未来扩展都够 | 🔴 **换芯片级重估**：flash 模式与封装、USB 通道（S3 的 USB-Serial/JTAG 与 PLL 约束）、分区表与 flash 容量、**ADC1 通道映射不同**（标定与分压网络要重算）、LEDC/I2C/SPI 行为差异、**功耗上升**（双核 → 直接冲击 README §3.3 的电池续航预算）、13 个信号的电气特性逐条重验 | ⚠️ **只在"未来确实要加很多真引脚外设"时才值得**；本项目当前 13 脚刚好够，**为余量付"整机重验 + 续航下降"不划算** |

#### (d) ⚠️ 换个角度 —— **本设计本来就是模块化子板结构** ✅

- 架构事实（[`hardware/README.md`](../hardware/README.md) §3、[`core-board/README.md`](../hardware/core-board/README.md)）：
  **130×95 mm 四层核心底板** + **6 组 2.54 mm 排母插座**，
  当前规划插入 5 个模块：`pa-module` / `lpf-module` / `atu-module` / `mcu-ui-module` / `power-module`。
- ⇒ **MCU 只属于 `mcu-ui-module` 这一块子板**，它与底板之间的**接口**（I²C / SPI / 编码器按键 / ADC 检波 / PWM / 键控）才是**冻结契约**（`docs/05`）。
  换 MCU 板**不动** PA / LPF / ATU / power / antenna / 底板。
- ⇒ "换板"的成本被**结构性限制**在：**`mcu-ui-module` 的 PCB + BOM + 固件 pin map + 重验**。
- ⚠️ **但不要把它误读成"零成本换板"**：
  ① **pin map 是冻结契约**，任何换板都要按 `docs/05` §6 重走（改文档 → 硬件确认 → 软件确认 → 评审 → 改回"冻结" → 同步代码）；
  ② **两种板子不可能共用同一封装**：SuperMini 是 **16 脚 2×8 排针**，LuatOS CORE 是 **21×51 mm 32 脚邮票孔**（官方文档）⇒ 仍要改 `mcu-ui-module` 的 PCB；
  ③ 本项目 BOM 把 U4 写成"2.54 mm 排针模组"，与官方"邮票孔"不一致 —— **下单/装配前必须核对实物引出形式**（只影响机械，不影响引脚账）。
- ⇒ 结论：**(d) 是对的视角**，它把换板从"整机重做"降级为"一块子板 + 固件重排"；但它**不能把换板的收益变成正的**，只是让代价可承受。

### 13.7 推荐：留在 LuatOS；若必须换，先满足三条前置条件

**推荐 (a) 留在合宙 LuatOS ESP32C3-CORE**，理由按权重：

1. 🔴 **换板买不到引脚**：两边都是"13 个信号用满、0 空闲"；SuperMini 只把 R1 换成了"LED + UART0"两项新约束。
2. 🔴 **R1 已经被工程手段守住**：构建期 DIO 断言（§12.1）+ 真机三重确认 `mode:DIO`（§9 附录 A）。
   换板消除的是**已缓解的风险**，代价却是**未验证的新风险**。
3. 🟠 **余量从 +2 掉到 0**：LuatOS 板的 GPIO20/21 现在还能在将来"备用串口不要了"时回收（§5.4.3 讨论过）；换到 SuperMini 后这两脚**开箱即被 PWM/SW 占用**。
4. 🟢 **零改动、零重验**：现状是唯一有**真机日志证据**的方案（§9），而 LED/天线/换号都要新的实测。

**若采购/尺寸/供货迫使换到 SuperMini**，三条前置条件（缺一不可）：

| # | 前置条件 | 验收方式 |
| --- | --- | --- |
| P-1 | **处置 GPIO8 的板载蓝 LED**（拆除 / 不装 / 断开），并在 BOM 与装配说明里写明 | 万用表确认 GPIO8 与 LED 网络断开；示波器看 EC11 静止高电平回到 ~3.3 V（详见 §13.9 的实测建议） |
| P-2 | **重排 pin map**：`PA_PWR_PWM`→GPIO20、`EC11_SW`→GPIO21，且 GPIO20 加**上电 10 kΩ 下拉**（把 A-7a 的建议一并落到新脚上） | 公开仓 5 处 + 私有仓 3 处同步（§8 清单）；`docs/05` §6 流程走完再改代码 |
| P-3 | **接受失去 UART0**，并确认控制台/ROM 日志全在原生 USB-Serial/JTAG（`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y` + `CONFIG_ESP_CONSOLE_ROM_SERIAL_PORT_NUM=3`） | 冷启动抓一次完整日志，确认 `ESP-ROM:` 与 `boot:` 行都从 USB 出来（不依赖 GPIO20/21） |

> 🔴 **本节不做决定**。若项目所有者选择 (b)，请按 `docs/05` §6 的变更流程发起，本节可作为变更的理由书与验收清单。

### 13.11 天线实况核实：**两块板都只有板载 PCB 天线，都没有 IPEX 座**（2026-09-27 追加）

> **触发问题**（项目所有者）：「想要 SuperMini，理由 = 更小 + **能外接 WiFi 天线**」。
>
> 🔴 **本节把"外接天线"这个理由查到底。结论是：这个理由不成立 —— 它不能把选型推向 SuperMini。**
> 本节只补事实与证据，**不改动 §13.1–§13.10 的任何既有一字**，也不改变任何引脚分配。

#### 13.11.1 结论先行

| 问题 | 答案 |
| --- | --- |
| 合宙 LuatOS ESP32C3-CORE **有 IPEX / U.FL 座吗**？ | 🔴 **没有。** 官方硬件资源清单写的是「**2.4G PCB 板载天线**」，32 脚定义里**没有任何天线脚**；官方原理图（KiCad 网表）里**不存在** IPEX/U.FL/天线座的位号或网络 |
| 那 LuatOS 板是**什么**天线？ | **PCB 蛇形（meander）印刷天线**，蚀刻在板子顶端（正面 `2.4G PCB板载天线` 区域），**集成在 PCB 上** |
| **能外接天线吗**？ | ✅ **能，但是"改板级"级别**：RF 走线是 `ESP32-C3 U2.LNA_IN → 匹配网络 → PCB 天线`，匹配网络里**有 0 Ω 串联器件**（原理图位号 `R2 0R`，另有 `C1/C2/C5/C10` 等焊盘，其中 `C2`、`C5` 标注 **`NF` = Not Fitted 未装配**）⇒ **理论落点**：断开 `R2`，把 50 Ω 同轴（IPEX 座 / 半刚性线）焊到 `LNA_IN` 一侧的匹配焊盘上 |
| 有没有**天线切换开关 / 0 Ω 跳线**？ | 🔴 **没有自动切换**。原理图里**没有 RF 开关**（无 `SKY13xxx` / `PE42xxx` / `U.FL` 之类的切换器件），也**没有标注"ANT 选择"的跳线**。要外接就得**动烙铁**，且**没有可回退的跳线**（拆下来的 0 Ω 要留着，想改回板载天线得焊回去） |
| SuperMini 有 IPEX 座吗？ | 🔴 **也没有。** 厂家（WMNologo）官方页在 "WiFi Antenna" 一节的原文是「If you want to use an external antenna, you can connect an external antenna **according to the following image**」，配图明确画的是 **① 屏蔽层（the shield layer）② 线芯（the wire core）** —— **即"把同轴线缆的芯线焊到板上的馈电焊盘"**，不是"插一个 IPEX 座"。它的板载天线是 **`CrossAir CA-C03` 陶瓷贴片天线**（原理图位号 `A1`，其中 `A1` 的 `0` 脚是 **NC/悬空**、`1` 脚接 RF 匹配网络） |
| SuperMini **射频体验**会更好吗？ | ⚠️ **未必，很可能更差**：陶瓷贴片天线（`CA-C03`）配这块板子的布局是**公认弱项**（天线离地平面太近、省掉了 datasheet 要求的净空与调谐短线）。二手资料（ESPboards）的原话：*"The ceramic antenna is the weak spot … WiFi range is weak. The cause is the layout, not the ESP32-C3"*。<br>**LuatOS 板的 PCB 蛇形天线在同类里属正常水平** |

#### 13.12.0 一句话决策建议（给项目所有者）

> 🔴 **不要为了"外接天线"换 SuperMini，也不建议仅为"更小"换。**
> 理由：① **天线理由已被证伪** —— 两块板都没有 IPEX 座，外接都得焊线，而 SuperMini 的陶瓷天线**开箱更弱**（§13.11）；
> ② 换板**买不到任何引脚**（13 → 13，余量 **+2 → 0**）；
> ③ 换板要**多付三项新成本**（拆 GPIO8 的灯、放弃 UART0、13 信号全量重验）去消除一项**已被构建期断言 + 真机三重确认守住**的风险（R1）。
> **推荐：留在 LuatOS ESP32C3-CORE。** 若确实要更小，请优先考虑 **§13.6(d) 的"只改 `mcu-ui-module` 子板"**（甚至自绘 PCB —— 那时**裸芯片 + 外置 flash** 既保住 GPIO12/13、又能**自己布 IPEX 座与 π 匹配**，收益远大于换开发板）。

#### 13.12.1 P-1 —— 处置 GPIO8 的板载蓝 LED（**必做，且必须先做**）

**为什么必须做（定量）** —— 依据厂家原理图 T-6，SuperMini 的蓝灯支路是：

```
+3.3V ──[ UR8  0201  5.1 kΩ ]──[ CD2  LED B 0603 ]──[ GPIO8 ]
                                                     ▲
                        GPIO8 另接：外部 10 kΩ 上拉(VCC)  ← 我们的 EC11_B 上拉
                                    与 EC11 的 B 相触点（旋转时对地短接）
```

| 影响 | 机理 | 量级 |
| --- | --- | --- |
| ① **常态偷电流** | GPIO8 常态为高（外部 10 kΩ 上拉）⇒ LED 阴极≈3.3 V、阳极经 5.1 kΩ 接 3.3 V ⇒ **两端等电位，LED 不亮** ✅ 好的一面 | — |
| ② **旋转时"长尾"漏电** | EC11 B 相触点接地 → GPIO8 被拉到 0 V ⇒ `3.3 V → 5.1 kΩ → LED(蓝, V_f≈2.7–3.0 V) → 0 V` ⇒ **LED 点亮**。电流 ≈ (3.3−2.8)/5.1 k ≈ **0.1 mA**，且**只在旋钮触点闭合的那一小段角度**流动 | 平均远小于 0.1 mA，但**与"人一直把旋钮停在触点闭合位置"耦合** |
| ③ **LED 与 10 kΩ 上拉构成分压器** | 即使 GPIO8 只做**输入**，LED 支路也是一个**对地的非线性负载**：在 0↔3.3 V 跳变沿附近，LED 的结电容与非线性会把上升沿拖慢、把高电平拉低一点点 | 定性（**具体压降必须实测**，见验收） |
| ④ **若 GPIO8 被驱动为低**（异常路径：其他驱动误配成输出低） | 上拉 10 kΩ 灌 0.33 mA 进 GPIO8 输出级 | 0.33 mA（无害，但说明"上拉很弱"） |
| ⑤ **待机预算** | 本项目按电池待机做预算（README §3.3）⇒ 任何**与功能无关的常态电流**都必须清掉 | 与 LuatOS 板拆 `D4/D5` 是**同一条理由** |

**🔴 结论：必须"断开"LED 支路，光靠软件驱动"强拉"解决不了 ③。**

| 处置方案 | 做法 | 评级 | 说明 |
| --- | --- | --- | --- |
| **P-1a（推荐）拆限流电阻 `UR8`** | 拆掉 0201 的 5.1 kΩ（**或**用热风/烙铁使其一端翘起） | ✅ **首选** | **LED 支路从"二极管 + 电阻"退化为"一个电阻 + 一个悬空 LED"** ⇒ 对 GPIO8 的负载只剩 5.1 kΩ 串联的**开路**（实际上 LED 侧悬空，等于断开）⇒ 电气上彻底干净；且**LED 仍焊在板上不会掉**，比拆灯珠好操作 |
| P-1b 拆 LED 灯珠 `CD2` | 直接拆 `LED B 0603` | ✅ 可行 | 同样达到"断开"，但 0603 灯珠比 0201 电阻**更怕热损伤**，且拆下来容易丢 |
| P-1c 割断 GPIO8↔LED 走线 | 刻断铜箔 | ⚠️ 最后手段 | 不可逆、易伤阻焊，且**无法回退** |
| P-1d 软件"强拉" | 把 GPIO8 配成开漏/输出低 | 🔴 **不行** | ① 与 10 kΩ 上拉**打架**（EC11_B 永远读不到高）；② **EC11_B 直接失效**；③ 解决不了 ③ 的容限问题 |
| P-1e 什么都不做 | — | ⚠️ **可评估，但不推荐** | 只有在"实测证明 EC11 计数无误 + 待机电流可接受"时才成立；**必须先做实测再决定** |

**⚠️ SuperMini 变体差异（必须逐板确认）**：`UR8` 的阻值在**不同厂家/版本**上可能**不是 5.1 kΩ**（本次取到的是 WMNologo 版 = **0201 5.1 kΩ**）。若某变体直接把 LED 接在 GPIO8 与 GND 之间**而不串电阻**，则 GPIO8 被硬钳在 ~1.0 V，**EC11_B 完全失效 ⇒ 该变体不可用**。⇒ **下单后第一件事就是照 §13.12.4 的"P-1 前置目视检查"核一遍。**

**验收（P-1）**：

```text
① 万用表（断电、二极管档/电阻档）：GPIO8 焊盘 ↔ 蓝灯阴极 → 应"开路/高阻"（改前是 ~5.1 kΩ 或二极管压降）
② 上电、固件在跑：示波器/万用表量 GPIO8（旋钮静止）→ 应 ≈3.3 V（不是 2.x V）
③ 旋转旋钮一整圈：GPIO8 应在 3.3 V ↔ ~0 V 之间完整跳变，**无中间平台、无拖尾**
④ 待机电流：与"未拆"对照，差值应 ≤ 数十 µA
⑤ 功能：EC11 正转/反转计数与时序（drv_ec11 的自检）全部通过
```

#### 13.12.2 P-2 —— 重排 pin map（`PA_PWR_PWM`→GPIO20、`EC11_SW`→GPIO21）

**信号落点（与 §13.3/§13.4 一致，此处不再重复论证）**：

| 我们的信号 | 现脚（LuatOS） | **新脚（SuperMini）** | 该脚在 SuperMini 上的角色 | 必须同步的硬件动作 |
| --- | --- | --- | --- | --- |
| `PA_PWR_PWM` | GPIO12 | **GPIO20** | `IO20 / RX` = **UART0 RXD**（复位后默认功能） | 🔴 **`GPIO20 → 升压模块 FB` 之间加 10 kΩ 下拉**（见下"为什么"） |
| `EC11_SW` | GPIO13 | **GPIO21** | `IO21 / TX` = **UART0 TXD**（复位后默认功能） | 保持原有 **10 kΩ 上拉**（接 GND 的按键，按下为低） |

**🔴 为什么 GPIO20 必须下拉（三条，缺一不可的理由）**：

1. **它是 ROM 的 UART0 RX 脚**：上电到 `bsp_board_init()` 之间若**浮空**，噪声可能在 ROM 的后备 UART 通道上产生伪起始位（`CONFIG_ESP_CONSOLE_ROM_SERIAL_PORT_NUM=3` 表示 ROM 控制台走 USB，但**引脚本身仍是 UART0 的 IO_MUX 默认功能**，直到固件显式改成 GPIO）。本例要把它变成**输出**，中间必然有一段"未被驱动"的窗口。
2. **它接的是升压模块的 FB 网络**：`docs/05` §2.10.2 的整条论证在这里**完全适用**（低 = 最低功率，浮空/高 = 有被推向满功率的风险）——**只是脚号从 12 换到了 20**。⇒ 这正好把 §7 #7a / A-7a 那条"📌 建议采纳未定"的 10 kΩ 下拉**顺势落实**。
3. **它是"上电即输出 0"的安全信号**：`bsp_board.c` 的三步顺序（`gpio_reset_pin → set_level(0) → config(输出+内部下拉)`）在 GPIO20 上**一模一样可用**（GPIO20 不是 strapping 脚，上电为低**不触发任何启动模式变化** —— 这一点比 §6.2 的 C′ 方案（PWM 落 GPIO2/8）**干净得多**）。

> 📌 **GPIO21 相对省心**：它是 ROM 的 UART0 **TX** 脚。`CONFIG_ESP_CONSOLE_UART_DEFAULT` 已关、`ESP_CONSOLE_UART_NUM=-1`，`docs/05`/`drv_ec11` 只把它当**输入 + 上拉**用 ⇒ ROM 即使在这根脚上打日志（见 P-3），**输入脚不受影响**，不会误触发中断（UART 空闲 = 高）。

#### 13.12.3 P-3 —— 控制台 / ROM 日志全在原生 USB-Serial/JTAG（**已确认 ✅**）

**核实结果（本机只读核对，三处一致）**：

| 证据 | 内容 | 判定 |
| --- | --- | --- |
| `sdkconfig:1668–1678` | `# CONFIG_ESP_CONSOLE_UART_DEFAULT is not set`<br>`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y`<br>`CONFIG_ESP_CONSOLE_SECONDARY_NONE=y`<br>`CONFIG_ESP_CONSOLE_UART_NUM=-1`<br>`CONFIG_ESP_CONSOLE_ROM_SERIAL_PORT_NUM=3` | ✅ 主控制台 = USB-Serial/JTAG，**UART 控制台已关闭**（`UART_NUM=-1`） |
| `sdkconfig.defaults:195–201` | 显式写 `CONFIG_ESP_CONSOLE_SECONDARY_NONE=y`，并注明「免得旧 `sdkconfig` 里残留的 `SECONDARY_USB_SERIAL_JTAG=y` 又冒出来」 | ✅ **默认值层面就锁住了**，不依赖某台机器的旧 sdkconfig |
| `sdkconfig:1220` / `:26` / `:722` | `CONFIG_USJ_ENABLE_USB_SERIAL_JTAG=y` · `CONFIG_SOC_USB_SERIAL_JTAG_SUPPORTED=y` · `CONFIG_ESP_ROM_CONSOLE_OUTPUT_SECONDARY=y` | ✅ SoC 能力齐备；**ROM 引导输出来自 `ESP_ROM_CONSOLE_OUTPUT_SECONDARY` 这一 SoC 能力**（`esp_rom/esp32c3` 的 `Kconfig.soc_caps.in` 恒为 1）⇒ **从上电第一行 `ESP-ROM:` 起就同时打到 USB** |
| `components/comm_console_usbcdc/README.md:27` | `ESP_ROM_USB_SERIAL_DEVICE_NUM (3) // UART uses USB_SERIAL_JTAG port in ROM.` | ✅ 与 `ROM_SERIAL_PORT_NUM=3` 对上 |
| 真机日志（§9 附录 A） | `rst:0x15 (USB_UART_CHIP_RESET)` + ROM banner 从 USB 出来 | ✅ **实测印证** |

**🔴 结论**：

1. **P-3 已满足，不需要任何改动。** 把 `PA_PWR_PWM`/`EC11_SW` 搬到 GPIO20/21 **不会**碰到控制台链路 —— 因为**控制台根本不在 UART0 上**。
2. **丢掉的是什么**：只有 ① **esptool 的 UART 下载通道**（我们一直用原生 USB 下载）② **"万一 USB 挂了"的救砖串口**。
   ⇒ 这是**唯一的实质损失**，且与 §13.4 G-4 的判断一致。
3. ⚠️ **一个新的、必须写进文档的运维注记**：换板后 **GPIO20/21 不再空闲** ⇒ **不能用它们接 USB-TTL 看日志**。
   调试**只能**走 Type-C 的原生 USB-Serial/JTAG（`VID:PID 303A:1001`）。若日后需要第二条日志通道，
   只能从 `TCA9535` 的空闲位腾（software UART **不推荐**：本项目有 400 Hz–20 kHz PWM 与 ADC 采样时序）。
4. 📌 **装配注记**：SuperMini 的 **BOOT 按键（`K1`）经 `UR6 = 10 kΩ` 上拉到 3.3 V**（原理图 T-6），
   与 LuatOS 板的"BOOT 靠板载上拉"**等价** ⇒ `BOARD_KEY_USER`(GPIO9) 的语义**不变**，无需额外硬件。

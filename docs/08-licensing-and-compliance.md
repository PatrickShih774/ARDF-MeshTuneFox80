## 1. 分层授权总表

本项目采用**分层授权**：不同目录适用不同协议，以匹配不同的商业意图。各许可全文放在 [`LICENSES/`](../LICENSES/README.md)，源文件头部带 **SPDX 标识符**。

> **为什么根目录没有单一 `LICENSE`**：根目录放一个 `LICENSE` 会让 GitHub 与所有代码扫描工具把**整个仓库**（含硬件与中控软件）判定为那一种许可，掩盖下面的区分。本项目采用 [REUSE](https://reuse.software/) 风格：全文放 `LICENSES/`，逐目录映射见 [`LICENSING.md`](../LICENSING.md)，源文件带 SPDX 头。代价是 GitHub 侧边栏显示 *"no license"*——对多许可仓库而言这比错误显示单一许可**更准确**。

### 1.2 双仓库结构

本项目采用**双仓库**结构，因为**源码保密与"公开仓库"在技术上不可兼得**——GitHub 的可见性是**仓库级**的，不是路径级：只要仓库是 public，`git ls-files` 中的每个文件（**含历史提交中的文件**）都可公开读取。

| 仓库 | 可见性 | 内容 | 许可 |
|------|--------|------|------|
| [`ARDF-MeshTuneFox80`](https://github.com/PatrickShih774/ARDF-MeshTuneFox80) | **公开** | 硬件设计、文档、**固件二进制（GitHub Releases）**；共享协议与中控 PC 软件（规划中，待创建） | `CERN-OHL-S-2.0` / `Apache-2.0` / `CC-BY-4.0` / `LicenseRef-ARDF-NC-1.0` |
| `ARDF-MeshTuneFox80-firmware` | **私有** | ESP32-C3 固件**全部源码**，不对外公开 | `LicenseRef-ARDF-NC-1.0` |

因此：

- 公开仓中**已不包含任何固件源码目录**；固件源码全部位于私有仓。任何固件源码片段（含 Issue / PR 描述、文档示例代码）都**不得**提交到公开仓，见 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 安全红线。
- 编译器产出的**固件二进制**通过公开仓的 **GitHub Releases** 发布，**不进入 Git 历史**。
- 跨仓引用需使用 GitHub 绝对 URL（`docs/` 与源码的改动不再落在同一次提交中）——这是双仓结构的已知代价。
- 决策背景与代价分析见 [ADR-0007](adr/ADR-0007-firmware-closed-source-two-repo.md)。

## 3. 为什么不再需要许可隔离

### 3.1 原方案及其废止原因

[ADR-0006](adr/ADR-0006-layered-licensing-gpl-isolation.md)（**已被 [ADR-0007](adr/ADR-0007-firmware-closed-source-two-repo.md) 取代**）曾设计「分层授权 + 工程隔离」：核心固件以**要求公开源码的许可**发布，闭源算法编译为**独立可执行程序**、运行于**独立固件分区**，通过 UART/SPI/I2C **进程间通信（IPC）** 调用，以避免闭源部分被该许可的义务覆盖。

该方案有**两处根本问题**：

1. **与项目目标直接冲突**：该许可要求"分发二进制即必须提供完整对应源码"，与"只发布编译产物、源码自行保留"的目标在法理上不可兼得。
2. **隔离设计缺乏法律确定性**：FSF 对"独立程序"的判定依赖具体事实（是否构成单一作品的衍生、是否共享数据结构、通信是否紧密耦合）；隔离设计降低了风险，但**不能保证**被认定为独立作品。

采用 [ADR-0007](adr/ADR-0007-firmware-closed-source-two-repo.md) 后，固件**整体闭源**并改用 `LicenseRef-ARDF-NC-1.0`：不存在"闭源部分被源码公开义务覆盖"的问题，**这套隔离机制从一开始就没有必要**。因此 ADR-0006 的结论整体作废，其文件仅作历史决策记录保留。

> 📌 原「隔离方案」的具体设计（独立可执行程序、独立算法分区、IPC 通道、安全启动相关的许可分析）**已从本文档删除**。历史细节见 [ADR-0006](adr/ADR-0006-layered-licensing-gpl-isolation.md)（**已被取代**）。

### 3.2 由此带来的架构简化

| 项目 | 原隔离方案（已废止） | 现行结构 |
|------|---------------------|---------|
| 固件分区 | 主固件 + 独立算法分区，双镜像管理 | **单一 `factory` 应用分区** |
| 算法调用方式 | 跨分区 IPC（UART/SPI/I2C 报文，非链接） | 同一进程内**函数直接调用** |
| 分区表 | 需自定义分区表、双镜像版本匹配校验 | 见 [03-软件架构](03-software-architecture.md)（已删除独立算法分区） |
| 性能与调试 | 跨分区调用有额外时延，需维护两套产物 | 无额外时延，单一构建产物 |
| 安全启动 / Flash 加密 | 受"必须提供安装修改后固件途径"的义务牵制 | **可自由启用 Secure Boot 与 Flash 加密** |
| 许可边界 | 依赖工程隔离规避义务，存在法律不确定性 | 公开仓四类映射 + 私有仓单独授权，边界清晰 |

### 4.2 🔴 ESP-IDF 的声明义务（闭源固件同样适用）

**ESP-IDF 采用 `Apache-2.0`，不是要求公开源码的强互惠许可。** 因此：

- ✅ **可以**：把 ESP-IDF 链接进**闭源**固件、静态编译并以二进制形式分发，**无需**公开固件源码或做出任何源码承诺。
- ⚠️ **必须**：Apache-2.0 第 4 条要求，分发目标代码时须
  (a) 随附许可副本；

  (c) 若上游提供 `NOTICE` 文件，须在分发中包含其内容。
- ⚠️ **适用场景**：本项目通过 **GitHub Releases 分发固件二进制**，因此上述义务**随二进制一并生效**——必须在 Release 页面、随附文档或固件的「关于」信息中提供这些声明。

> **闭源 ≠ 可以省略第三方声明。** 已创建仓库根 [`NOTICE`](../NOTICE) 登记全部第三方组件；
> **发布 Release 时必须随附**（见 §6 第 7–8 项）。

## 5. 射频合规

### 5.1 ARDF 信号源的法规定位

| 场景 | 要求 |
|------|------|
| **持证火腿自用** | ✅ 合法。ARDF 信号源属于业余电台专用设备。 |
| **未组装套件销售** | ⚠️ 通常不视为无线电发射设备整机；**建议明示**"组装后使用需持证并办理设台手续"。 |
| **成品整机对公销售** | 🔴 **需要 SRRC（国家无线电监测中心）型号核准**。 |
| **教学仪器类目** | ⚠️ 监管实践中通常按器材销售，但**法律层面无明文豁免**；销售前应与当地无线电管理机构预沟通。 |

### 5.2 技术合规依据

| 规则要求 | 本项目实现 | 依据 |
|---------|-----------|------|
| A1A 调制 | GPIO 键控方波，软起软降 2–5 ms | 《业余无线电测向竞赛规则》第十四条 |
| 垂直极化 | 5 m 垂直导线 + 5 m 地线 | 第十四条 |
| 频率稳定度 ≤50×10⁻⁶ | Si5351 晶振精度 ±20–50 ppm | 第十四条 |
| 谐波抑制 | 三阶椭圆低通，2f₀ 衰减 ≥55 dB | 第十四条 |

### 5.3 出口与型号核准

- 若出口，需核对目标国法规（如 FCC Part 97 对应美国业余业务）。
- 型号核准（SRRC）测试需覆盖：频率范围、发射功率、杂散辐射、占用带宽。

## 7. 贡献者许可约定

提交代码/设计即表示同意按下表授权：

| 贡献区域 | 授权协议 |
|---------|---------|
| `hardware/` | `CERN-OHL-S-2.0` |
| `software/master-console/`（规划中，待创建）、`software/protocol/`（规划中，待创建）、`software/tools/`（规划中，待创建）、`scripts/` | `Apache-2.0` |
| `docs/`、`validation/` | `CC-BY-4.0` |
| **固件源码** | **不接受外部贡献**（私有仓，非公开） |

- 贡献者**保留版权**，当前不要求签署 CLA。
- 🔴 **固件源码不接受外部贡献**：固件源码位于私有仓，公开仓无法接收也不会合并固件补丁。任何固件源码片段——包括 Issue 与 PR 描述——都不得提交到本公开仓，见 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 安全红线。
- 若未来为支持双许可模式而引入 CLA，须提前在 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 中公告。

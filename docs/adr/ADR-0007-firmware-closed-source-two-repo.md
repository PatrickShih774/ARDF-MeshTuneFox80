# ADR-0007 固件闭源与双仓结构

- 状态：已接受
- 日期：2026-09
- 决策者：项目负责人

## 背景

项目最初采用**单仓库 + 固件 GPL-3.0-or-later** 的方案（见
[ADR-0006](ADR-0006-layered-licensing-gpl-isolation.md)）。该方案有两处根本问题：

### 1. 目标与许可冲突

项目希望**只开源编译后的固件**，源码自行保留。但 GPL 第 3 条要求：一旦分发二进制，
就必须向接收者提供**完整对应源码**。在 GPL 下，"只发布二进制"在法理上不成立。

而 ADR-0006 为绕开 GPL 传染性设计的「闭源算法编译为独立可执行程序 + 独立 `algo` 分区 +
进程间通信」方案，带来了：

- 额外的分区与 IPC 复杂度；
- 性能与调试成本（进程间通信替换直接函数调用）；
- **法律不确定性**——FSF 对"独立程序"的判定依赖具体事实，
  工程隔离不构成法律担保（ADR-0006 已自述"不是法律担保"）。

更关键的是：如果固件整体都闭源，**这套隔离机制从一开始就没有必要**——
它解决的正是"闭源部分被 GPL 传染"的问题，而整体闭源时该问题不存在。

### 2. 公开仓库无法隐藏源码

GitHub 的可见性是**仓库级**的，不是路径级。任何被 `git add` 过的文件——包括
**历史提交中的文件**——在 public 仓库中都公开可读。因此"源码放在公开仓但不开源"
在技术上不可实现。

## 决策

**拆分为两个仓库，固件源码完全私有，公开仓只发布编译产物。**

| 仓库 | 可见性 | 内容 | 许可 |
|------|--------|------|------|
| `ARDF-MeshTuneFox80` | **公开** | 硬件设计、文档、共享协议、中控软件、**固件二进制（Releases）** | `CERN-OHL-S-2.0` / `Apache-2.0` / `CC-BY-4.0` / `LicenseRef-ARDF-NC-1.0` |
| `ARDF-MeshTuneFox80-firmware` | **私有** | ESP32-C3 固件全部源码 | `LicenseRef-ARDF-NC-1.0` |

### 固件许可

弃用 `GPL-3.0-or-later`，改用自定义许可 **`LicenseRef-ARDF-NC-1.0`**
（「ARDF 业余无线电非商业许可 1.0」，全文见
[`LICENSES/LicenseRef-ARDF-NC-1.0.txt`](../../LICENSES/LicenseRef-ARDF-NC-1.0.txt)）。

| | 内容 |
|---|---|
| **覆盖范围** | **仅编译后的二进制形式**，不覆盖源码 |
| **授予** | 业余无线电用途的安装、运行、使用；个人备份；非商业性再分发完整原始副本 |
| **不授予** | 源代码的任何权利 |
| **不要求** | 权利人无义务提供源码；许可不要求任何人公开源码 |
| **禁止** | 商业性使用、修改与逆向工程、移除版权标识 |

### 连带废止

- [ADR-0006](ADR-0006-layered-licensing-gpl-isolation.md) 的 GPL 隔离方案**整体作废**
  （状态改为「被取代」）。
- [docs/03-software-architecture.md](../../docs/03-software-architecture.md) 分区表中的
  `algo` 分区**删除**。
- 公开仓历史**重写**，彻底移除固件源码与 GPL 全文。

## 后果

### 正向

- **目标达成**：源码保密，仅发布二进制。
- **架构简化**：不再需要 `algo` 分区、独立可执行程序、IPC 通道；
  固件恢复为单一 `factory` 应用，函数直接调用。
- **许可清晰**：不存在 copyleft 传染问题，不存在反 Tivoization 义务，
  可以自由启用 Secure Boot / Flash 加密。
- **硬件仍完全开源**：`CERN-OHL-S-2.0` 不变，社区可自行做板、卖套件。
- **协议与中控仍开放**：第三方可基于公开协议自行实现上位机。

### 负向与代价

- **失去社区贡献**：外部无法提交固件补丁，"社区版长期存在"的保障消失
  （这正是当初选 GPL 的理由）。
- **信任成本**：用户只能拿到二进制，无法审计固件行为。对涉及**射频发射**的设备，
  这会降低部分用户的信任。缓解措施：公开固件的**行为规格**
  （[docs/03](../../docs/03-software-architecture.md) 的组件划分与接口）、
  公开**验证报告**（[validation/](../../validation/README.md)），做到"可验证不可修改"。
- **历史重写**：公开仓需 force push 覆盖历史；已 clone 的副本需重新拉取。
  （本决策执行时仓库仅建立 1 天，0 star / 0 fork，无外部影响。）
- **双仓维护成本**：跨仓引用需用 GitHub 绝对 URL，`docs/` 与源码的改动不再在同一次提交中。
- **仍需遵守 Apache-2.0**：ESP-IDF 是 `Apache-2.0`，其版权声明与 NOTICE 必须随二进制分发。
  闭源**不等于**可以省略第三方声明。

### 法律边界备注

本 ADR 不构成法律意见。自定义许可 `LicenseRef-ARDF-NC-1.0` 未经司法检验，
其「商业性使用」边界（尤其"非营利赛事组织者"与"收费培训"的区分）在争议中
可能存在解释空间。**正式商业化前需律师复核**。

## 备选方案

| 方案 | 结论 |
|------|------|
| 维持单仓 + GPL 3.0（现状） | ❌ 与"只开源二进制"目标直接冲突 |
| 单仓 + 源码可见但限制性许可（source-available，如 PolyForm Noncommercial） | ❌ 源码仍公开可见，未达成保密目标；且 GitHub 不会标为 open source |
| 闭源算法独立可执行 + `algo` 分区（ADR-0006） | ❌ 整体闭源后该隔离失去意义，徒增复杂度与法律不确定性 |
| **双仓 + 自定义非商业许可** | ✅ **采用** |
| 私有主仓 + CI 推送公开镜像 | ❌ 需维护跨仓同步逻辑，收益不抵复杂度 |
| 固件用 MIT/Apache-2.0（仅覆盖二进制） | ❌ 无法阻止他人复制固件用于竞品 |
| 固件用专有许可（免费使用 + 禁止再分发/逆向） | 未采用；选择了允许非商业再分发的较宽松形式 |

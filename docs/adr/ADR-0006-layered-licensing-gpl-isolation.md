# ADR-0006 分层授权与 GPL 隔离方案

- 状态：**已被取代**（由 [ADR-0007 固件闭源与双仓结构](ADR-0007-firmware-closed-source-two-repo.md) 取代）
- 日期：2026-09
- 决策者：项目组

> ⚠️ **本 ADR 的结论已作废，仅作为历史决策记录保留。**
>
> 固件不再使用 `GPL-3.0-or-later`，改为自定义许可 `LicenseRef-ARDF-NC-1.0`
> （仅限业余无线电非商业用途），源码移入私有仓。**整体闭源后不存在 copyleft 传染问题**，
> 因此「独立可执行程序 + `algo` 分区 + 进程间通信」的隔离设计**失去意义**，已全部废止：
>
> - [docs/03-software-architecture.md](../../docs/03-software-architecture.md) 分区表中的 `algo` 分区已删除
> - 固件恢复为单一 `factory` 应用分区，函数直接调用，不再有 IPC 通道
> - [LICENSING.md](../../LICENSING.md) 与 [docs/08](../../docs/08-licensing-and-compliance.md) 的相关章节已重写
>
> 取代理由与新的结构设计见 [ADR-0007](ADR-0007-firmware-closed-source-two-repo.md)。

## 背景

项目希望同时达成两个看似冲突的目标：**社区版长期开源**（核心固件不能被闭源 fork 后回流失社区）
与**商业授权可行**（ATU 调谐算法、Mesh 路由算法是核心技术积累，需通过闭源商业授权支撑持续开发）。

核心矛盾在于 **GPL 3.0 的传染性**：若把闭源算法直接编译进 GPL 固件，会与 GPL 条款冲突；
反之若全部 Apache 化，则失去 copyleft 保护。此外硬件设计也需明确许可，避免"可否商用"的歧义。

## 决策

采用**分层授权 + 工程隔离**：

| 层 | 许可 | 说明 |
| --- | --- | --- |
| 核心固件 | **GPL 3.0** | 社区版固件，长期开源 |
| 中控 PC 基础版 | **Apache 2.0** | 宽松许可，便于集成与二次开发 |
| 通信协议定义 | **Apache 2.0** | 规范公开，鼓励第三方实现 |
| 硬件设计 | **CERN-OHL-S v2** | 开源硬件许可 |
| ATU 调谐算法 | **商业授权（闭源）** | 闭源组件 |
| Mesh 路由算法 | **商业授权（闭源）** | 闭源组件 |

**隔离方式**：闭源算法编译为**独立可执行程序**，运行于**独立固件分区**；
GPL 固件**不链接**其代码，只通过 **UART / SPI / I2C 进程间通信（IPC）** 调用，
以报文（复用共享协议 `software/protocol/`（规划中，待创建）的风格）交换参数与结果。

配套要求：

- 每个目录必须能明确判定适用许可；仓库根与各子目录的 `README.md` 中标注许可，第三方组件登记许可证台账（见 `docs/08-licensing-and-compliance.md`）。
- 闭源分区与 GPL 分区之间的接口定义必须公开、稳定、可被第三方复现。

> **法律边界备注：工程隔离不等于法律担保。**
> 上述方案是基于常见实践的工程安排，**不构成法律意见**；
> 正式商业化前必须由**执业律师复核**分区、链接方式、IPC 接口与分发方式的合规性。

## 后果

**正向**

- 双层商业模式可行：社区版保持 GPL 开源，商业版以闭源算法增值。
- 许可边界清晰，贡献者能明确知道自己的提交会以何种许可发布。
- IPC 接口公开，第三方亦可自行实现算法替换闭源组件，生态不被锁死；copyleft 保护亦生效。

**负向**

- **增加分区与 IPC 复杂度**：需自定义分区表、双镜像管理、版本匹配校验。
- **性能与调试成本上升**：跨分区调用有额外时延，调谐过程的实时性需重新评估
  （目标仍是首次调谐 <5s，见 `validation/stage-5-tuning-algorithm/`）。
- 闭源部分的缺陷排查更困难；分发时需严格区分"社区版包"与"商业版包"，构建与发布流程须支持两套产物。
- **法律风险未被消除，只是被降低**，商业化前必须律师复核。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 全部 GPL 3.0 | 拒绝：放弃闭源商业授权，无法支撑持续开发 |
| 全部 Apache 2.0 | 拒绝：放弃 copyleft 保护，易被闭源 fork 回流失社区 |
| 仅提供源码、不做任何隔离 | 拒绝：闭源算法将被迫以 GPL 发布，与商业目标直接冲突 |
| 闭源算法放云端服务 | 暂不考虑：赛场常无网络，离线可用性是硬需求 |

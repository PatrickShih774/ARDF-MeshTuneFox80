# ADR-0004 12864 液晶走 I2C 共享总线

- 状态：已接受
- 日期：2026-09
- 决策者：硬件组 / 固件组

## 背景

ESP32-C3 的可用 GPIO **仅 15 个**：GPIO0–10 与 GPIO18–21；
**GPIO11–17 被 SPI Flash 占用**，不可用作外设。

而系统需要的外设接口却相当多：

| 需求 | 接口需求 |
| --- | --- |
| 模拟采样（前向/反射检波、电池电压、温度等） | **4–5 路 ADC** |
| ATU 匹配网络 | **6 路继电器驱动** |
| 用户输入 | **编码器 3 线 + 双按键** |
| 显示 | **LCD**（12864） |
| 功放调压 | **1 路 PWM** |
| CW 键控 | **1 路数字输出** |

若按"每个外设独占 GPIO"的直连方式分配，引脚必然不足，且 PCB 布线会极其拥挤。

## 决策

采用**显示与慢速 IO 全部挂共享总线**的方案：

1. **LCD**：选用支持 **ST7567 I2C 模式**的 12864 模块，与 Si5351、TCA9535 共享 **I2C 总线**。
2. **TCA9535 I/O 扩展器**：所有慢速 IO 挂扩展器——
   **6 路继电器、编码器、双按键、LCD RST / 背光**。
3. **稀缺 GPIO 优先留给高速与模拟功能**：
   - ADC：**GPIO0–4**；
   - CW 键控：**GPIO7**；
   - 功放调压 LEDC：**GPIO8**。

即：把"慢"的信号全部搬到 I2C 上，把"快"和"模拟"的信号留在原生 GPIO 上。

## 后果

**正向**

- GPIO 分配留有余量（预留 GPIO9/10 作为备用），后续加功能不必改板。
- 布线显著简化：多条控制线收敛为 2 根 I2C 线。
- I2C 器件可级联，扩展性好，BOM 元件数可控；慢速 IO 的时序抖动对系统无影响。

**负向**

- **LCD 全屏刷新在 400kHz 下约 25ms**，因此必须实现**局部刷新**，且刷新期间不得长时间占用总线。
- **I2C 总线成为共享故障点**：任一器件拉低 SDA/SCL 都会拖垮整条总线，需要超时恢复机制（总线复位、SCL 打拍恢复）。
- 需明确**总线优先级与互斥**：LCD 刷新、Si5351 频率设置、继电器动作必须串行化，由统一的总线管理器加锁。
- 增加 TCA9535 与驱动代码复杂度，继电器动作经由扩展器后时延略有增加（可接受）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| SPI 模式 LCD | **备用方案**：占用 4 个 GPIO，在 I2C 方案受阻时启用，预留 GPIO9/10 |
| 并口 8080 LCD | 拒绝：引脚不足，直接否决 |
| 再挂 SPI 扩展器 | 拒绝：无必要，I2C 带宽已满足慢速 IO 需求 |
| 减少 ADC 通道数 | 拒绝：会牺牲 SWR 与温度测量精度，影响 ATU 判决 |

> 📌 **后继变更（2026-09-26）——本 ADR 正文保持原样，不改写历史，仅加此注**：
> 上表把「温度」列为 ADC 通道需求之一的前提**已不再成立**。NTC 功放温度功能已由用户决策
> **整体取消**（12 个可用 GPIO 已全部用满、**ADC1 没有可分配给 NTC 的空闲通道**；
> 硬件同步从 PA 模块 BOM 删除 NTC）。实际 ADC 需求为 **3 路**（前向检波 / 反射检波 / 电池电压）。
> **本 ADR 的结论（LCD 挂共享 I²C、避免并口 8080）不受影响**——
> 它依赖的是"引脚总数不足"，而这一点没有变化。
> 完整记录见 [docs/17 §12.5](../17-gpio-allocation-audit.md)。
